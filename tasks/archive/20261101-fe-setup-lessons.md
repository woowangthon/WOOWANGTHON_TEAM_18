## Lessons

- **Scaffolding tools drift.** The Vite template changed linters and TypeScript major versions since the last time we used it; read what it generated before assuming ESLint-era setup.
- **Make tools not depend on `.gitignore` to skip `node_modules`.** An explicit `ignorePatterns` keeps lint output sane in CI, in worktrees and in temp copies. *(Pitfalls candidate)*
- **Stacked PRs: save the "A" version of shared files before building B on top.** With nothing committed, `package.json`, the lockfile, `App.tsx` and `ai-scope.md` are touched by both PRs; keeping copies made it possible to verify that A passes on its own.
- Mutation testing was not run: no mutation tool is chosen yet ([`docs/conventions.md`](../../docs/conventions.md) §6). Say so in the PR body instead of leaving the checkbox ticked.
- **Tech names live only in the `docs/system-definition.md` §3 table (§7, agreed 2026-11-01).** SRS, flows, ADRs and diagrams use component names (FE, BE). Tools go to `docs/conventions.md` §6, `CLAUDE.md` Commands and `docs/ai-scope.md`. Check this before writing any SRS row. *(Pitfalls candidate)*
- **One commit per concern.** A 23-file commit with a 3,500-line lockfile cannot be reviewed. Split by category and derive each stage's lockfile so every commit stays green.
- Design PR follow-ups: its SRS rows (they cite `jsx-a11y` and test file paths) must follow the tech-names rule too, and its body must say the temporary style guide page was deleted after the screenshots were taken.
- **`engines.node` is the intersection of the dependencies' `engines`.** Read them in `pnpm-lock.yaml` (jsdom, vitest, vite) instead of copying the lowest number from one tool. *(Pitfalls candidate)*
- **Pin GitHub Actions to commit SHAs and bump them by hand.** `v4` can be an annotated tag: dereference it to the commit, and check which release the tag really points to (here `pnpm/action-setup` `v4` = v4.3.0 although v4.4.0 exists).
