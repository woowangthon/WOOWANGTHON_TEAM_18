## Lessons

- **Probe the real answer before writing the contract.** Two design decisions came straight from probes (the `sha` media type, and the tree-SHA trap: `git/trees` accepts a tree SHA but `raw` answers 404 for it, which would have turned every `package.json` into a silent "unreadable"). Neither was in any doc.
- **A client-sent `commit` is a read parameter, not a trusted value.** It is fine for a read-only draft of a public repo. "The commit that was scanned equals the commit in the saved spec" has to be checked by the server in the save task, so the server needs to remember the commit it pinned.
- **Remove a defensive line when no real case needs it.** The one real mutant survivor was `trim()` on an answer that is exactly 40 bytes; failing closed (503) is the safer behavior than accepting a padded value.
- **The mutant runner must run the tests that can see each file, and `pnpm verify` is the only gate.** Same mistake twice: a mutant on the rules file survived because only unit tests ran.
- **When a reviewer's "high" finding contradicts a test that passes, run the test first.** GPT-OSS's two "high" findings were disproved by existing tests in seconds.
- **Do not promise a notification you did not arrange.** Use a background watcher or `--wait` with a real wait.
