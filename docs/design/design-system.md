## 범위

FE가 화면을 만들기 전에 쓸 **토큰과 기본 컴포넌트 6종**(`Button`, `Input`, `Badge`, `Table`, `Card`, `LogBlock`)을 정한다. 코드는 `FE/src/styles/`, `FE/src/components/ui/`에 있다.

- 하는 것: 흑백 미니멀(Vercel식), 정보 밀도 높게, 한글과 영문이 한 줄에 섞이는 화면(`nginx:1.27`, `Running 2/3`)을 기준으로 한다. 다크 모드는 OS 설정(`prefers-color-scheme`)을 따른다.
- 하지 않는 것: 수동 다크 모드 토글, 라우터, 실제 화면, 위 6종 밖의 컴포넌트, 변종 라이브러리, 기성 컴포넌트 키트(shadcn/ui 등).
- 컴포넌트를 눈으로 확인하려고 임시 스타일 가이드 페이지를 두었다가 삭제했다. 컴포넌트와 토큰만 남기고, 화면은 PR에 첨부한 스크린샷(라이트 · 다크, 1440px · 390px)으로 남긴다.

## 설계

스타일링은 Tailwind CSS v4이고, 토큰은 설정 파일 없이 CSS의 `@theme`에 선언한다. 색은 `:root`의 CSS 변수(라이트 기본, 다크는 값만 교체)를 만들고 `@theme inline`이 그 변수를 가리킨다. 이렇게 해야 다크 모드에서 클래스가 아니라 변수 값만 바뀐다.

`@theme` 첫머리에서 `--color-*`, `--text-*`, `--radius-*`, `--shadow-*`, `--font-*`를 `initial`로 비워서 Tailwind 기본값이 모두 사라진다. 그래서 `bg-indigo-500`, `shadow-lg`, `rounded-xl`, `text-3xl` 같은 클래스는 존재하지 않는다 (빌드 결과로 확인함).

### 색

| 토큰 | 라이트 | 다크 | 쓰임 |
| --- | --- | --- | --- |
| `bg` | `#ffffff` | `#000000` | 페이지 배경 |
| `surface` | `#f4f4f4` | `#141414` | 표 머리글, 로그 블록, 비활성 컨트롤 배경. `bg`와 1.10:1(라이트) · 1.14:1(다크)로 떨어져 있어 단계로 보인다 |
| `fg` | `#0a0a0a` | `#ededed` | 본문, 기본 버튼 배경(primary = 검정, 다크에서 흰색) |
| `muted` | `#666666` | `#a1a1a1` | 보조 글씨 |
| `line` | `#e5e5e5` | `#262626` | 구분선, 카드 · 표 테두리 (장식) |
| `line-strong` | `#8f8f8f` | `#6e6e6e` | 입력 · 외곽 버튼 테두리 (조작 요소 경계, 3:1 이상) |
| `ok` | `#0a7d33` | `#3ecf6e` | Running 등 정상 |
| `warn` | `#a15c00` | `#f5a524` | Pending 등 주의 |
| `err` | `#c4210f` | `#ff6166` | Failed 등 오류 |
| `info` | `#0059c8` | `#52a8ff` | Updating 등 진행 중 |

텍스트 대비는 `FE/src/styles/theme.test.ts`가 `theme.css`에서 읽어 계산한다. 글씨로 쓰는 쌍은 `bg`와 `surface` 위에서 모두 4.5:1 이상(라이트 최저 4.72:1, `warn` on `surface`. 다크 최저 6.28:1), 경계선 `line-strong`은 `bg` 위에서 3:1 이상(라이트 3.23:1)이다. `line-strong`을 `surface` 위에 올리면 라이트에서 2.94:1이라 3:1에 못 미치므로, 조작 요소의 경계는 `bg` 위에 둔다. 상태는 색만으로 전달하지 않고 배지 안의 글자(`Running`, `Failed`)로도 전달한다.

### 글꼴 · 크기 · 모양

| 항목 | 값 |
| --- | --- |
| 본문 · 제목 | `NSN`(나눔스퀘어 네오) 400/700/800, 대체 글꼴 `Apple SD Gothic Neo` → `Malgun Gothic` → `system-ui` |
| 로그 · 코드 | 나눔고딕코딩 (Google Fonts), 대체 `ui-monospace`, `Consolas` |
| 글자 크기 | `xs` 12/16, `sm` 13/20, `base` 14/22(본문 기본), `lg` 16/24, `xl` 20/28, `2xl` 28/36 (px, 글자 / 줄 높이) |
| 모서리 | `sm` 4px, `md` 6px |
| 그림자 | 없음 (Tailwind 기본을 비움. 모달이 생기면 그때 토큰을 추가한다) |
| 테두리 | 1px |
| 숫자 | 본문에 `font-variant-numeric: tabular-nums`를 두지만 나눔스퀘어 네오에서는 효과가 없다(측정: `1111` 24px, `0000` 40px). 표의 숫자 열은 우측 정렬 + 고정폭 글꼴(`font-mono`)로 자릿수를 맞춘다 |
| 줄바꿈 | `word-break: keep-all`로 한글을 공백에서만 끊는다. 표 셀은 줄바꿈 없이 가로 스크롤하고, 배지도 줄바꿈하지 않는다 |
| 로그 레벨 | `LogBlock`은 문자열 children(문자열 조각 포함)의 `INFO`(`muted`), `WARN`(`warn`), `ERROR`(`err`) 단어에만 색을 입힌다. 글자는 그대로라 색만으로 전달하지 않는다 |
| 포커스 | 2px 실선 `fg`, 오프셋 2px (키보드 포커스만) |
| 비활성 | `opacity`를 쓰지 않는다. 불투명도는 배경과 글씨를 함께 옅게 해서 글씨 대비가 1.55:1까지 떨어졌다. 대신 `surface` 배경 + `line` 테두리 + `muted` 글씨(`surface` 위에서 4.5:1 이상, 테스트가 확인)로 그린다 |

## 결정과 대안

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| Tailwind CSS v4 + `@theme` 토큰 | 간격 · 반응형 · 상태(hover, focus)를 클래스로 빠르게 처리하고, 빌드 시점에 CSS가 만들어져 런타임 비용이 없다. 3일 일정에 맞다 | 순수 CSS(간격 · 상태를 전부 손으로 써야 해서 느림), SCSS(변수는 편하지만 간격 유틸리티가 없어 이득이 작음), Emotion(런타임 CSS-in-JS로 렌더마다 JS 비용이 들고, 전담 디자인 시스템 팀이 있는 조직에 맞는 방식) |
| 기본 팔레트를 비우고 흑 · 백 · 회색과 의미 색 4개만 노출 | Tailwind가 "AI가 만든 것 같아" 보이는 이유는 라이브러리가 아니라 기본 팔레트(인디고 · 보라)와 기본 모양이다. 클래스 자체가 없으면 실수로 쓸 수 없다 | 기본 팔레트를 두고 쓰지 않기로 약속하기 |
| 컴포넌트는 직접 만든 작은 React 컴포넌트, 변종은 TS 객체 맵 | 6종뿐이라 variants 라이브러리가 필요 없다 ([conventions F-2](../conventions.md)). 기성 키트(shadcn/ui 등)는 가장 흔한 "AI 룩"의 출처이고 코드가 늘어난다 | shadcn/ui, 변종 라이브러리 |
| 나눔스퀘어 네오 단독(본문 · 제목 · 한영 혼용) | 한글과 영문이 한 줄에 섞이는 화면이라 글꼴 하나로 높이와 굵기를 맞추는 편이 낫다 | 영문 전용 글꼴 + 한글 글꼴 조합 (줄 높이 · 굵기가 어긋남) |
| 글꼴은 CDN으로 불러오고 `font-display: swap` | 저장소에 글꼴 파일을 넣지 않는다. 쓰는 굵기만 내려받는다 | 글꼴 파일을 저장소에 포함 |
| `className` prop은 간격 · 배치(margin, width, flex)에만 쓴다. 컴포넌트가 정한 높이 · 색 · 모서리 · 글자 크기를 바꾸려면 variant를 추가한다 | Tailwind는 클래스 순서가 아니라 CSS 순서로 이겨서 `<Button className="h-10">`이 `h-8`을 덮어쓰지 못한다. `cn()`(`clsx` + `tailwind-merge`)은 쓰는 쪽이 없는 지금은 의존성만 늘어 F-2에 걸려 보류했다 | `cn()` 지금 도입 |
| 다크 모드는 `prefers-color-scheme`만 따름 | 토글 UI와 저장 로직이 필요 없다 | 수동 토글 |
| 표 숫자 열만 고정폭 글꼴 | `tabular-nums`가 나눔스퀘어 네오에서 듣지 않아 `12.5%`, `3.0%`의 소수점과 `2/3`, `1/1`의 슬래시가 행마다 흔들렸다. 이미지 태그 열이 이미 고정폭이라 한 행에 글꼴 두 개가 섞이는 것은 새 문제가 아니다 | 나눔스퀘어 네오 유지(정렬이 흔들림), 숫자 전용 글꼴 추가(요청이 3종으로 늘어남) |
| Google Fonts 스타일시트는 `media="print"` + `onload`로 비차단 | 느리거나 막힌 CDN이 첫 화면을 붙잡지 않는다. 응답을 4초 늦춘 측정에서 FCP가 4.6초에서 1.1초로 줄었다. 정상 네트워크에서는 차이가 없다(1.20초 대 1.20초) | 렌더 차단 스타일시트 유지 |

## 알려진 한계

- 나눔스퀘어 네오 woff는 굵기 하나가 약 0.7MB이고 서브셋이 아니다. 쓰는 굵기(400 · 700 · 800)를 합치면 약 2.2MB이며 첫 방문에는 네이버 CDN 응답에 의존한다. `font-display: swap`이라 받는 동안 대체 글꼴로 보이고, CDN이 막히면 대체 글꼴로 남는다.
- 400만 프리로드한다. 700 · 800은 첫 렌더 뒤에 요청돼 늦게 도착한다(1.6Mbps 제한에서 400은 약 10.6초, 700 · 800은 약 11.5초). 대부분의 UI가 700이라 그 사이 굵은 글씨는 대체 글꼴로 보인다. 700 프리로드를 시험했더니 FCP가 1.20초에서 1.52초로 늦어지고 도착 시점은 거의 같아서(11.1초) 넣지 않았다. 대역폭이 좁을 때 프리로드는 첫 화면 리소스와 경쟁한다. 글꼴 서브셋이 생기면 다시 본다.
- 공식 웹폰트에는 SemiBold(600)가 없어 700을 쓴다.
- 나눔스퀘어 네오 숫자는 `tabular-nums`를 켜도 고정 폭이 아니다(측정으로 확인). 그래서 표 숫자 열만 고정폭 글꼴을 쓴다. 표 밖의 숫자(본문, 카드 안의 수치)는 여전히 자릿수가 맞지 않는다.
- 다크 모드는 화면 캡처로 눈으로만 확인했다. 대비는 스크립트로 계산했지만 실제 기기 · 모니터에서의 가독성은 확인하지 않았다.
- 글꼴 라이선스 전문(OFL)은 직접 읽지 않았다. 근거와 확인 범위는 [`ai-scope.md`](../ai-scope.md) §4.
- `Input`은 보이는 라벨을 만들지 않는다. 쓰는 쪽이 이름을 줘야 하고 타입이 `aria-label` 또는 `aria-labelledby` 중 하나를 강제한다. `<label htmlFor>`로만 이름을 주는 방식은 타입을 통과하지 못하므로, 그렇게 쓸 화면이 생기면 이 타입을 고친다. `Table`과 `LogBlock`은 스크롤 영역이라 이름(`aria-label`)을 필수 prop으로 받는다.
- 컨트롤 · 표 본문 · 표 머리글 · 로그는 13px(`text-sm`), 본문은 14px, 배지만 12px다. 표 머리글과 로그는 12px일 때 한글 획이 얇아 읽기 어려워 13px로 올렸다(밀도는 조금 줄어든다). 배지는 높이 18px를 지키려고 12px로 둔다. 1px 차이는 위계로 읽히지 않고 밀도를 위한 값이다.
- 표 안의 고정폭 글꼴(이미지 태그, 숫자)도 13px다. 12px였을 때 같은 행의 `shop-api`(나눔스퀘어 13px)보다 눈에 띄게 작고 가벼웠다.
- 컨트롤 높이 32px는 WCAG 2.5.8 최소(24px)는 넘지만 모바일 터치 권장(44px)에는 못 미친다. 모바일 화면을 만들 때 다시 본다.
- 표는 모바일에서 줄바꿈 대신 가로 스크롤이다. 390px에서 표 폭(507px)이 화면(356px)보다 커서 Pods · CPU 열이 스크롤 뒤로 간다. 열 우선순위는 실제 화면을 만들 때 정한다.
- `Table`은 내용 폭(`w-fit max-w-full`)이다. 전체 폭으로 늘리는 방법이 없다. `className`은 `<table>`에 붙어서 바깥 영역의 폭은 못 바꾸므로, 필요한 화면이 생기면 `Table`을 고친다.
- 로그 레벨 색은 단어 매칭이라 본문 속 `ERROR`도 칠해지고, 문자열 children(`{ts} INFO {msg}`처럼 섞인 조각 포함)에만 적용되며 요소 children(`<b>`)은 그대로 둔다. 줄 형식을 아는 파서가 아니다.
- 팔레트와 모양(`#fafafa` · `#0a0a0a`, 1px 선, 4px 모서리, 외곽선 배지)이 Vercel 계열과 겹쳐 기성 키트처럼 보일 수 있다. 의도된 선택이고, 정체성은 나눔스퀘어 네오와 고정폭 토큰에 둔다.
- 입력 글자 크기가 13px이라 iOS Safari에서는 포커스할 때 화면이 확대된다. 모바일 화면을 만들 때 다시 본다.
- 테스트는 CSS를 읽지 못해(Vitest가 CSS를 비운다) 토큰 없는 클래스(`bg-white` 등)를 잡지 못한다. 대신 린트(`eslint-plugin-better-tailwindcss`)가 `className`과 `variants` 객체 값을 검사한다. `no-unknown-classes`(기준은 `theme.css`)는 미정의 클래스를, `no-restricted-classes`는 임의값(`bg-[#6366f1]`, `rounded-[12px]`), 로드하지 않은 굵기(`font-semibold` 등, 400 · 700 · 800만 있다), 그림자 계열(`drop-shadow-*`, `ring-*` 등)을 막는다. 임의값은 유효한 Tailwind 클래스라 `no-unknown-classes`만으로는 통과했다(프로브로 확인). 임의 변형(`[&_tr]:border-b-0`)은 막지 않는다. 다른 이름의 객체나 `clsx` 같은 호출은 검사하지 않으므로, 그런 패턴을 쓰면 `eslint.config.js`의 `selectors`에 더한다(`selectors`를 주면 기본 목록이 통째로 바뀐다).
