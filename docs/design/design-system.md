## 설계

스타일링은 Tailwind CSS v4이고, 토큰은 설정 파일 없이 CSS의 `@theme`에 선언한다. 색은 `:root`의 CSS 변수(라이트 기본, 다크는 값만 교체)를 만들고 `@theme inline`이 그 변수를 가리킨다. 이렇게 해야 다크 모드에서 클래스가 아니라 변수 값만 바뀐다.

`@theme` 첫머리에서 `--color-*`, `--text-*`, `--radius-*`, `--shadow-*`, `--font-*`를 `initial`로 비워서 Tailwind 기본값이 모두 사라진다. 그래서 `bg-indigo-500`, `shadow-lg`, `rounded-xl`, `text-3xl` 같은 클래스는 존재하지 않는다 (빌드 결과로 확인함).

### 색

| 토큰 | 라이트 | 다크 | 쓰임 |
| --- | --- | --- | --- |
| `bg` | `#ffffff` | `#000000` | 페이지 배경 |
| `surface` | `#f4f4f4` | `#141414` | 표 머리글, 로그 블록, 비활성 컨트롤 배경. `bg`와 1.10:1(라이트) · 1.14:1(다크)로 떨어져 있어 단계로 보인다 |
| `fg` | `#0a0a0a` | `#ededed` | 본문, 기본 버튼 배경(primary = 검정, 다크에서 흰색) |
| `muted` | `#666666` | `#a1a1a1` | 보조 글씨 |
| `line` | `#e5e5e5` | `#262626` | 구분선, 카드 · 표 테두리 (장식) |
| `line-strong` | `#8f8f8f` | `#6e6e6e` | 입력 · 외곽 버튼 테두리 (조작 요소 경계, 3:1 이상) |
| `ok` | `#0a7d33` | `#3ecf6e` | Running 등 정상 |
| `warn` | `#a15c00` | `#f5a524` | Pending 등 주의 |
| `err` | `#c4210f` | `#ff6166` | Failed 등 오류 |
| `info` | `#0059c8` | `#52a8ff` | Updating 등 진행 중 |
| `raise` | `#ffffff` | `#0a0a0a` | 배너 · 선택 행처럼 `bg` 위로 올라온 면 |
| `accent` | `#f7941d` | `#f7941d` | 기본 버튼 배경, 완료 단계 점. 글씨를 얹지 않는다 |
| `accent-fg` | `#0a0a0a` | `#0a0a0a` | `accent` 위의 글씨 (두 모드 모두 검정) |
| `accent-text` | `#b45309` | `#f7941d` | 링크처럼 `bg` · `surface` 위에 놓는 주황 글씨 |
| `accent-ui` | `#d97706` | `#f7941d` | 활성 탭 · 메뉴 밑줄, 미터 막대, 스피너, 포커스 링 (비글씨 3:1) |
| `accent-soft` | `#fff1de` | `#2b1a06` | 선택된 행의 배경 |

포인트 색은 기본 버튼 · 링크 · 활성 탭과 메뉴 밑줄 · 미터 · 완료 단계 · 포커스 링에만 쓴다. 상태 색(`ok` · `warn` · `err` · `info`)과 겹치지 않게 상태는 글자나 기호로도 구분한다. `accent-ui`는 `bg` · `raise` 위에서 3:1 이상이지만(`Meter` 막대 바탕도 `bg`다) 라이트 `surface` 위에서는 2.90:1이라 거기에는 올리지 않는다. 선택된 행의 테두리(`accent-ui`)는 `accent-soft` 바탕이 아니라 주변 `bg`와의 대비로 본다(바탕과는 2.87:1).

텍스트 대비는 `FE/src/styles/theme.test.ts`가 `theme.css`에서 읽어 계산한다. 글씨로 쓰는 쌍은 `bg`와 `surface` 위에서 모두 4.5:1 이상(라이트 최저 4.57:1, `accent-text` on `surface`. 다크 최저 6.28:1), 경계선 `line-strong`은 `bg` 위에서 3:1 이상(라이트 3.23:1)이다. `line-strong`을 `surface` 위에 올리면 라이트에서 2.94:1이라 3:1에 못 미치므로, 조작 요소의 경계는 `bg` 위에 둔다. 상태는 색만으로 전달하지 않고 배지 안의 글자(`Running`, `Failed`)로도 전달한다.

| 모서리 | `sm` 4px, `md` 6px |

| 비활성 | `opacity`를 쓰지 않는다. 불투명도는 배경과 글씨를 함께 옅게 해서 글씨 대비가 1.55:1까지 떨어졌다. 대신 `surface` 배경 + `line` 테두리 + `muted` 글씨(`surface` 위에서 4.5:1 이상, 테스트가 확인)로 그린다 |

### 새 컴포넌트 (2026-11-13)

| 컴포넌트 | 쓰임 | 규칙 |
| --- | --- | --- |
| `Tabs` · `Tab` | 같은 화면 안의 보기 전환 | `role="tablist"` · `role="tab"`, 활성은 `active` prop → `aria-selected`, 굵은 글씨, `accent-ui` 밑줄. 활성 탭만 Tab 순서에 들어가고 좌우 화살표 · Home · End가 탭 사이로 초점을 옮긴다(선택은 Enter · Space). 어느 탭이 활성인지는 화면이 정한다. 경로를 바꾸는 메뉴는 탭이 아니라 상단 바의 `NavLink`처럼 쓴다 |
| `Spinner` | 버튼 처리 중 · 1~10초 대기 | `role="status"`와 이름. 모션을 줄이면 멈추지 않고 천천히 돈다(0.8초 → 2.4초) |
| `Skeleton` | 모양을 아는 콘텐츠의 첫 로딩 | `aria-hidden`. 반짝임 1.4초, 모션을 줄이면 단색 |
| `Banner` | 제목 없는 한 줄 안내 4종(info · ok · warn · err) | SVG 기호를 함께 둔다(원 `i` · 체크 · 삼각형 · ×라서 색을 못 봐도 경고와 오류가 갈린다). `err`만 `role="alert"` |
| `Steps` | 세로 단계(완료 · 진행 · 대기 · 실패 · 예정) | 진행 중 · 대기 · 실패는 상태 글자가 눈에 보이고(완료 · 예정은 스크린 리더용), 대기는 점선 테두리 + `…`라 진행 중(실선)과 모양으로 갈린다. `accent-ui`와 `warn`은 색이 가까워(다크 1.12:1, 라이트 1.63:1) 구분 수단으로 못 쓴다. 진행 중 단계는 `aria-current="step"` |
| `Meter` | 개수를 아는 진행 · 사용량 | `role="progressbar"`, 0~100%로 자른다 |
| `Sparkline` | 시간에 따른 값의 작은 선 그래프(서비스 CPU · 메모리) | 라이브러리 없는 인라인 SVG. 축 대신 최저 · 최고 · 지금 값을 글자로 두고 요약을 `aria-label`에 넣는다. `null`인 자리는 선을 끊고(없는 값을 지어내지 않는다), 값이 하나도 없으면 선 없이 `emptyText`만 보인다. 선 색은 `accent-ui`라 `bg` · `raise` 위에 둔다 |

로딩 선택: 목록 · 카드 첫 로딩은 `Skeleton`, 버튼 처리 중과 단계 진행은 `Spinner` + 문구, 개수를 아는 진행은 `Meter`, 300ms 안에 끝나는 일은 표시하지 않는다. 키프레임과 색 섞기가 필요한 `Skeleton` · `Spinner`는 임의값 클래스가 막혀 있어서 `theme.css`의 `@utility`(`skeleton`, `spinner`)로 둔다.

### 상단 바

`FE/src/layout/AppLayout.tsx`. 로고(`public/logo.png`) · 주 메뉴 · 이메일 · 로그아웃. 활성 메뉴는 굵은 글씨와 `accent-ui` 밑줄이다. 로고 PNG는 흰 배경이라 다크에서는 밝은 칩(`bg-fg`) 위에 올린다(투명 배경 로고가 생기면 칩을 뺀다). 본문 폭은 이번에 바꾸지 않았다(D1 · D2에서 화면과 함께 정한다).

### 나머지 화면 (D2, 2026-11-13)

로그인 · 가입 · 비밀번호 재설정은 `AuthCard`가 틀을 맡는다: 로고만 있는 상단 바 + 최대 440px 카드. 제목 아래에 한 줄 부제(`text-muted`)를 둔다. 제목과 설명이 있는 안내는 `components/NoticeBanner.tsx`가 `ui/Banner`를 감싸 그린다(기호 + 굵은 제목 + 설명, 역할은 이전 `Alert`와 같다). 링크는 `accent-text`, 경로를 옮기는 주 동작은 `primaryLinkClass`(Button primary와 같은 모양)를 `<Link>`에 붙인다. 목록 첫 로딩은 `Skeleton` + 기다림 글자다. 관리자 화면의 노드 사용량 `Meter`는 서버가 사용량을 수집했고 할당 가능량을 읽은 노드에만 그린다. 아니면 "수집 전" 글자만 둔다. 표 안의 `sr-only`는 `absolute`라서 기준 요소가 없으면 표의 스크롤 영역 밖으로 문서 폭을 늘린다(390px에서 가로 스크롤을 만들었다). 그 칸에 `relative`를 준다.

**공개 랜딩** (`FE/src/pages/LandingPage.tsx`, 경로 `/`): 로그인하지 않은 사람에게 보이는 첫 화면이다. 로그인한 사용자는 `/dashboard`로 보낸다. 문구는 이미 구현된 것만 말한다(운영자 승인 · 보안 검토 · 제품 일러스트 캐러셀은 와이어프레임에 있지만 빼거나 만들지 않았다). 와이어프레임의 `[예: ...]` 자리 문구와 DB 선택 문구도 확인된 사실이 아니라서 넣지 않았다.

### 알려진 한계 (D0)

- 라이트의 주황이 둘이다. 버튼 · 완료 점은 `accent`(`#f7941d`), 밑줄 · 미터 · 스피너 · 포커스 링은 `accent-ui`(`#d97706`)다. 글씨 대비 때문에 값이 갈렸고 토큰은 정해진 값이라, 한 카드 안에서 나란히 놓으면 밝기가 다르게 보인다. 다크는 같다.
- 포커스 링과 활성 탭 밑줄이 같은 주황이다. 활성 탭은 굵은 글씨 + 밑줄, 포커스는 둘레 상자라 모양으로 갈리지만 둘 다 주황이다. 링을 `fg`로 바꾸면 더 분명해지나 포커스 링 = `accent-ui`는 정해진 값이다.
- 라이트 `surface` 위의 포커스 링은 3:1 미만이다(`accent-ui` 2.90:1). 2px 띄운(`outline-offset`) 링이 `bg` 위에 놓여 실제로는 영향이 작지만, 재지 않았다.
- `Spinner`는 `role="status"`와 `aria-label`만 있어 읽어 주지 않을 수 있다. 화면이 옆에 기다림 글자를 함께 둔다.
- 다크 로고는 투명 배경 로고가 생길 때까지 밝은 칩 위에 있다.
- (해결됨, D1) `Steps`의 상태 글자와 `DeployStages`의 글자를 맞췄다. 배포 단계 목록은 이제 `Steps`를 쓰고, 글자는 '완료' · '진행 중' · '입력 대기' · '실패' · '예정' 다섯 가지다. 더 잘게 나뉜 상태(문제 해결 중, 사용자 조치 필요, 배포 대기, 건너뜀)는 같은 글자 아래 설명(`note`)으로 보탠다. `aria-current="step"`은 진행 중과 입력 대기 단계에 단다.
- 헤더(`max-w-300`)와 본문(`max-w-3xl`)의 왼쪽 선이 다르다. 화면을 만지는 D1 · D2에서 맞춘다. 본문으로 건너뛰기 링크도 아직 없다.

## 결정과 대안

| 결정 | 이유 | 버린 대안 |
| --- | --- | --- |
| Tailwind CSS v4 + `@theme` 토큰 | 간격 · 반응형 · 상태(hover, focus)를 클래스로 빠르게 처리하고, 빌드 시점에 CSS가 만들어져 런타임 비용이 없다. 3일 일정에 맞다 | 순수 CSS(간격 · 상태를 전부 손으로 써야 해서 느림), SCSS(변수는 편하지만 간격 유틸리티가 없어 이득이 작음), Emotion(런타임 CSS-in-JS로 렌더마다 JS 비용이 들고, 전담 디자인 시스템 팀이 있는 조직에 맞는 방식) |
| 기본 팔레트를 비우고 흑 · 백 · 회색과 의미 색 4개만 노출 | Tailwind가 "AI가 만든 것 같아" 보이는 이유는 라이브러리가 아니라 기본 팔레트(인디고 · 보라)와 기본 모양이다. 클래스 자체가 없으면 실수로 쓸 수 없다 | 기본 팔레트를 두고 쓰지 않기로 약속하기 |

## 알려진 한계

- 나눔스퀘어 네오 woff는 굵기 하나가 약 0.7MB이고 서브셋이 아니다. 쓰는 굵기(400 · 700 · 800)를 합치면 약 2.2MB이며 첫 방문에는 네이버 CDN 응답에 의존한다. `font-display: swap`이라 받는 동안 대체 글꼴로 보이고, CDN이 막히면 대체 글꼴로 남는다.
- 400만 프리로드한다. 700 · 800은 첫 렌더 뒤에 요청돼 늦게 도착한다(1.6Mbps 제한에서 400은 약 10.6초, 700 · 800은 약 11.5초). 대부분의 UI가 700이라 그 사이 굵은 글씨는 대체 글꼴로 보인다. 700 프리로드를 시험했더니 FCP가 1.20초에서 1.52초로 늦어지고 도착 시점은 거의 같아서(11.1초) 넣지 않았다. 대역폭이 좁을 때 프리로드는 첫 화면 리소스와 경쟁한다. 글꼴 서브셋이 생기면 다시 본다.
- 공식 웹폰트에는 SemiBold(600)가 없어 700을 쓴다.
- 나눔스퀘어 네오 숫자는 `tabular-nums`를 켜도 고정 폭이 아니다(측정으로 확인). 그래서 표 숫자 열만 고정폭 글꼴을 쓴다. 표 밖의 숫자(본문, 카드 안의 수치)는 여전히 자릿수가 맞지 않는다.
- 다크 모드는 화면 캡처로 눈으로만 확인했다. 대비는 스크립트로 계산했지만 실제 기기 · 모니터에서의 가독성은 확인하지 않았다.
- 글꼴 라이선스 전문(OFL)은 직접 읽지 않았다. 근거와 확인 범위는 [`ai-scope.md`](../ai-scope.md) §4.
- `Input`은 보이는 라벨을 만들지 않는다. 쓰는 쪽이 이름을 줘야 하고 타입이 `aria-label` 또는 `aria-labelledby` 중 하나를 강제한다. `<label htmlFor>`로만 이름을 주는 방식은 타입을 통과하지 못한다. 보이는 라벨이 필요한 폼은 `Field`를 쓴다. `Field`는 `<label>`과 오류 문구를 만들고 `aria-labelledby` · `aria-invalid` · `aria-describedby`를 이어 주며(`id`와 aria는 prop으로 받지 않는다), 입력칸 오른쪽에 붙는 버튼은 `trailing`으로 받는다. 그래서 `Input`의 타입은 고치지 않았다. 오류 테두리는 `className`이 아니라 `Input`의 `aria-invalid:border-err`로 그린다. `Alert`는 `err` · `warn` · `info` 세 가지이고 제목 글자가 필수다(색만으로 전달하지 않는다). `err`는 `role="alert"`, 나머지는 `role="status"`다. 제출 중은 버튼 글자와 `aria-busy`로 알리고, 눈에 보이는 대기 표시가 필요하면 `Spinner`를 쓴다. `Table`과 `LogBlock`은 스크롤 영역이라 이름(`aria-label`)을 필수 prop으로 받는다.
- 컨트롤 · 표 본문 · 표 머리글 · 로그는 13px(`text-sm`), 본문은 14px, 배지만 12px다. 표 머리글과 로그는 12px일 때 한글 획이 얇아 읽기 어려워 13px로 올렸다(밀도는 조금 줄어든다). 배지는 높이 18px를 지키려고 12px로 둔다. 1px 차이는 위계로 읽히지 않고 밀도를 위한 값이다.
- 표 안의 고정폭 글꼴(이미지 태그, 숫자)도 13px다. 12px였을 때 같은 행의 `shop-api`(나눔스퀘어 13px)보다 눈에 띄게 작고 가벼웠다.
- 컨트롤 높이 32px는 WCAG 2.5.8 최소(24px)는 넘지만 모바일 터치 권장(44px)에는 못 미친다. 모바일 화면을 만들 때 다시 본다.
- 표는 모바일에서 줄바꿈 대신 가로 스크롤이다. 390px에서 표 폭(507px)이 화면(356px)보다 커서 Pods · CPU 열이 스크롤 뒤로 간다. 열 우선순위는 실제 화면을 만들 때 정한다.
- `Table`은 내용 폭(`w-fit max-w-full`)이다. 전체 폭으로 늘리는 방법이 없다. `className`은 `<table>`에 붙어서 바깥 영역의 폭은 못 바꾸므로, 필요한 화면이 생기면 `Table`을 고친다.
- 로그 레벨 색은 단어 매칭이라 본문 속 `ERROR`도 칠해지고, 문자열 children(`{ts} INFO {msg}`처럼 섞인 조각 포함)에만 적용되며 요소 children(`<b>`)은 그대로 둔다. 줄 형식을 아는 파서가 아니다.
- 팔레트와 모양(`#fafafa` · `#0a0a0a`, 1px 선, 4px 모서리, 외곽선 배지)이 Vercel 계열과 겹쳐 기성 키트처럼 보일 수 있다. 의도된 선택이고, 정체성은 나눔스퀘어 네오와 고정폭 토큰에 둔다.
- 입력 글자 크기가 13px이라 iOS Safari에서는 포커스할 때 화면이 확대된다. 모바일 화면을 만들 때 다시 본다.
- 테스트는 CSS를 읽지 못해(Vitest가 CSS를 비운다) 토큰 없는 클래스(`bg-white` 등)를 잡지 못한다. 대신 린트(`eslint-plugin-better-tailwindcss`)가 `className`과 `variants` 객체 값을 검사한다. `no-unknown-classes`(기준은 `theme.css`)는 미정의 클래스를, `no-restricted-classes`는 임의값(`bg-[#6366f1]`, `rounded-[12px]`), 로드하지 않은 굵기(`font-semibold` 등, 400 · 700 · 800만 있다), 그림자 계열(`drop-shadow-*`, `ring-*` 등)을 막는다. 임의값은 유효한 Tailwind 클래스라 `no-unknown-classes`만으로는 통과했다(프로브로 확인). 임의 변형(`[&_tr]:border-b-0`)은 막지 않는다. 다른 이름의 객체나 `clsx` 같은 호출은 검사하지 않으므로, 그런 패턴을 쓰면 `eslint.config.js`의 `selectors`에 더한다(`selectors`를 주면 기본 목록이 통째로 바뀐다).
