# 구현·AI 범위와 출처

> **AI 활용도 10점**과 대회 공개 범위 규칙([`hackathon.md`](hackathon.md) §구현 및 공개 범위)의 근거 문서.
> 발표 부록에 **이 문서의 표를 그대로** 옮긴다.
>
> 갱신 시점 — 같은 커밋에서 고친다:
> - AI 모델·외부 API·라이브러리·데이터셋을 추가/교체/제거할 때
> - 코드에 `MOCK(<id>)`·`SAMPLE(<id>)` 마커를 넣거나 뺄 때 ([`conventions.md`](conventions.md) §1)
> - AI 기능의 검증 상태가 바뀔 때

## 1. 직접 구현 vs 외부 기술

| 구분 | 무엇 | 우리가 한 일 |
| --- | --- | --- |
| 직접 구현 | AI 에이전트(문제 티켓 처리 · 게이트웨이 도구 · 해결 결과 형식 · 실패 처리), 플랫폼 서버의 배포 설정 초안(레포 설정 파일로 프레임워크 판별, 규칙 코드) · 보안 검사 호출 · 쿠버네티스 호출 모듈(비밀값 · 조치 · 조회), 배포 파이프라인 정의(매니페스트 생성 · 적용 · 동작 확인 · 되돌리기), 스파이크 판정 규칙, 클러스터 구성(`Infra/`: 학생 공간 틀 · 권한 · 네트워크 정책) | 우리가 설계 · 구현 |
| 외부 기술 | React + TypeScript (Vite), Nest.js, FastAPI (FE · BE 버전은 각각 `FE/package.json` · `BE/package.json`에 고정, AI는 `AI/uv.lock`에 고정) | FE는 `FE/`에 Vite 템플릿으로 세팅하고 데모 코드를 제거함(패키지 매니저는 pnpm이고 버전은 `FE/package.json`의 `packageManager`로 고정. lint는 ESLint(typescript-eslint, jsx-a11y), 테스트는 Vitest + Testing Library + jsdom. TypeScript는 typescript-eslint가 7을 지원하지 않아 6.0으로 고정). BE는 `BE/`에 Nest 12(ESM)로 세팅함(pnpm. lint는 ESLint 10(typescript-eslint), 테스트는 Vitest + `@nestjs/testing` + supertest, 설정 읽기는 `@nestjs/config`이고 값 검증은 직접 구현. 헬스 체크 `GET /api/health`, CORS 허용 목록, 오류 응답 형식, 로그인 토큰 검증과 `GET /api/me`(아래 jose 행), 레포 소유 확인 `POST /api/repos/check`와 Dockerfile 확인 `POST /api/repos/dockerfiles`, 배포 설정 초안 `POST /api/repos/deploy-spec`(아래 Supabase · GitHub API 행)가 있고 그 밖의 기능은 구현 전). AI는 `AI/`에 Python 3.12 + FastAPI로 세팅함(의존성 · 잠금은 uv, lint · format은 ruff, 타입 검사는 mypy strict, 테스트는 pytest + FastAPI `TestClient`(httpx2). 설정 읽기는 pydantic-settings이고, 틀린 값이면 변수 이름만 담은 오류로 부팅을 멈춘다(값은 출력하지 않음). 서버 실행은 uvicorn. 헬스 체크 `GET /health`, 플랫폼 서버가 부르는 티켓 접수 `POST /agent/tickets`). 종료 알림 `POST /agent/tickets/{ticketId}/close`(서버 사이 토큰 검사, 티켓 · 결과 모양 검증, 아래 에이전트 행)가 있고 그 밖의 기능은 구현 전). 프레임워크 사용 |
| 외부 기술 | Tailwind CSS v4 (`@tailwindcss/vite`) | 스타일링 도구. 기본 팔레트를 비우고 흑백 토큰만 `@theme`에 선언. 컴포넌트 6종(Button · Input · Badge · Table · Card · LogBlock)은 직접 구현하고 기성 컴포넌트 키트는 쓰지 않음 |
| 외부 기술 | eslint-plugin-better-tailwindcss (FE devDependency, MIT) | 개발 도구. 린트에서 `theme.css`에 정의되지 않은 Tailwind 클래스(`bg-white` 등)를 막는다. 앱 번들에는 들어가지 않음. `no-unknown-classes`(없는 클래스)와 `no-restricted-classes`(임의값 · 로드하지 않은 굵기 · 그림자 계열) 두 규칙만 켰다 |
| 외부 기술 | react-router (FE dependency, MIT) | 라우팅 라이브러리. `BrowserRouter` · `Routes`는 그대로 쓰고, 경로 6개(`/login` `/signup` `/reset-password` `/dashboard` `/profile` `/deploy/new`)를 직접 이었다. 앞의 셋은 공개, 뒤의 셋은 로그인해야 열리는 보호 라우트(`FE/src/auth/RequireAuth.tsx`)이고 비로그인 방문자는 원래 가려던 경로를 담아 `/login`으로 보낸다. 경로마다 열리는 페이지와 보호 동작을 자동 테스트(`FE/src/App.test.tsx`)로 확인했다. 회원가입 · 비밀번호 재설정 화면(`SignupPage` · `ResetPasswordPage`)은 구현했고, 각 화면의 동작은 Supabase 대역으로 한 자동 테스트로 확인했다 |
| 외부 기술 | Docker 이미지 `node:22-bookworm-slim` (빌드), `nginx:1.27-alpine` (정적 서빙) | `FE/Dockerfile`로 로컬 컨테이너 개발용 이미지를 만든다. 운영 배포는 S3 + CloudFront라 이 이미지는 쓰지 않는다. 이미지 빌드와 nginx 동작(SPA 경로, 캐시 헤더, gzip)은 2026-11-03에 로컬에서 확인했고, CI에서는 이미지를 빌드하지 않는다 |
| 외부 기술 | Docker 이미지 `python:3.12-slim-bookworm` (AI 빌드 · 실행), uv `0.11.32`(빌드 단계에서 PyPI로 설치) | `AI/Dockerfile`로 AI 서버 이미지를 만든다(운영 배포는 EC2). 이미지 빌드, 헬스 체크 응답, root가 아닌 사용자로 실행, 개발 의존성 없음, 설정이 없으면 부팅 중단은 2026-11-10에 로컬에서 확인했고, CI에서는 이미지를 빌드하지 않는다 |
| 외부 기술 | Docker 이미지 `node:22-bookworm-slim` (BE 빌드 · 실행) | `BE/Dockerfile`로 BE 이미지를 만든다. 로컬 개발과 운영(EC2, `Infra/aws/deploy-be.sh`)이 같은 이미지를 쓴다. 이미지 빌드, 헬스 체크 응답, CORS 헤더, root가 아닌 사용자로 실행, 잘못된 설정에서 부팅 중단은 2026-11-04에 로컬에서 확인했고, CI에서는 이미지를 빌드하지 않는다 |
| 외부 기술 | jose (BE에서 Supabase 로그인 토큰 서명 검증, 공개 키 목록 받기 · 캐시) | 라이브러리 사용. 전역 가드(`@Public()` 예외, 401 · 503 구분, 관리자 판단)는 직접 구현. 테스트에서 만든 키로 서명한 토큰으로 위조 · 만료 · 발급자 · 대상 · 관리자 판단 · 인증 서버 장애 경로를 자동 테스트했다. 2026-11-04에 실제 Supabase 프로젝트로 띄워(로컬 · 컨테이너) 공개 키 목록을 받아 위조 토큰을 401로 거부하는 것과, 인증 서버에 닿지 못하면 503인 것을 확인했다. 같은 날 개발용 테스트 계정의 진짜 로그인 토큰으로 `GET /api/me`가 `200`을 주고, 서명이나 `app_metadata`를 바꾼 토큰은 `401`인 것을 확인했다 |
| 외부 기술 | PydanticAI (AI 서버의 에이전트 프레임워크. 도구 호출 · 출력 검증 · MCP 클라이언트 · 모델 전환. LangChain · LangGraph 대신. 워크플로우 상태는 플랫폼 서버가 가지므로 그래프 상태 저장이 필요 없다). `pydantic-ai-slim[openai,mcp]` 2.66(MIT)과 그것이 끌어오는 `openai` · `mcp` · `fastmcp-slim`(MCP 클라이언트) | 에이전트 흐름 · 도구 · 출력 스키마 · 가림 필터는 직접 설계 · 구현([`design/AIagent.md`](design/AIagent.md), `AI/ai_server/agent/`). 라이브러리로 쓰는 것: `Agent`(출력 모양 검증과 다시 만들기), `MCPToolset`(게이트웨이 연결. 거절 코드를 원본으로 보려고 상속해 `direct_call_tool`을 바꿈), `OpenAIChatModel` · `OpenAIProvider`(OpenAI 호환 API로 두 모델 연결), `FallbackModel`(추론 API를 못 쓰면 로컬로), `WrapperModel`(가림 필터를 끼우는 자리). 자동 테스트는 `FunctionModel`(대역 모델)과 FastMCP 대역 게이트웨이(`fastmcp-slim[server]`, 개발 의존성)로만 했고 실제 모델 · 게이트웨이는 부르지 않았다 |
| 외부 API | LLM API (업체·모델 미정) | 배포 실패 에이전트의 planning용 추론 모델 API는 OpenAI 호환 주소 · 모델 이름 · 키를 env(`PLANNER_MODEL_*`)로 받게 구현했다(업체는 미정이고 실제로 불러 본 적은 없다). 로컬 모델(리더 vLLM)도 같은 방식으로 `LOCAL_MODEL_*`로 받는다. 둘 다 선택이고, 로컬 모델 설정이 없으면 문제 해결을 하지 않는다고 알린다. 시스템 프롬프트 · 프롬프트 조립(`AI/ai_server/agent/prompts.py`)과 보내기 직전 가림 필터(`AI/ai_server/agent/redact.py`)는 직접 구현 |
| 외부 기술 | AWS — CodeBuild(빌드), S3 + CloudFront(웹 정적 파일), EC2 한 대(Nest · FastAPI · GoCD 서버. Kafka 브로커는 후순위) | CodeBuild를 부르는 빌드 스테이지(`Infra/pipeline/src/build.ts`: 서비스별 `StartBuild` 병렬, `BatchGetBuilds` 대기, digest, 실패 phase · 로그 200줄)와 공용 buildspec · 빌드 스크립트(`Infra/build/`)는 직접 구현했다. aws CLI를 셸 없이 부르고, 테스트는 aws CLI · git · docker 대역으로만 했다. 실제 CodeBuild 프로젝트 · IAM · Secrets Manager는 아직 만들지 않았고 실제 빌드로 돌려 본 적이 없다(**미검증**: buildspec의 `exported-variables`, `on-failure: ABORT`, CodeBuild 안의 `iptables`(메타데이터 주소 차단) 동작, CloudWatch 로그 읽기 모양). S3 + CloudFront · EC2는 구현 전. 플랫폼 FE · BE를 올리는 스크립트(`Infra/aws/`)와 설정값을 SSM Parameter Store에 두는 방식([`design/platform-hosting.md`](design/platform-hosting.md))은 작성만 했고 실제 AWS에서 돌려 보지 않았다(**미검증**) |
| 외부 기술 | GHCR (학생 앱 이미지 레지스트리, 이미지 공개. [ADR-003](adr/003-registry-ghcr.md)) | 빌드 스크립트가 봇 계정 토큰으로 `ghcr.io/<봇 계정>/student-apps:<slug>-<서비스>-<해시 12자>`에 push하고 digest를 넘긴다(구현함, 대역으로만 시험. 실제 push는 **미검증**). 봇 계정 · 패키지 공개 설정은 구현 전 |
| 외부 기술 | Docker 이미지 `node:<nodeVersion>-bookworm-slim`(빌드 · 서버 실행), `nginxinc/nginx-unprivileged:1.27-alpine`(정적 서빙, root가 아닌 사용자), Dockerfile 문법 `docker/dockerfile:1` — 학생 레포에 Dockerfile이 없을 때 쓰는 플랫폼 기본 Dockerfile(`Infra/build/dockerfiles/`: vite-react · nextjs · nest) | Dockerfile은 직접 작성. 2026-11-10에 로컬 docker로 vite-react(SPA 경로 · 빌드 env 공백 · 따옴표 · `=` 값, 사용자 101)와 nest(node 사용자, 시작 명령이 PID 1, 종료 0.7초)를 빌드 · 실행해 확인했다(npm 명령으로. pnpm은 샌드박스 프록시 인증서 때문에 corepack이 받지 못해 확인 못 함). nextjs는 nest와 같은 틀이고 따로 빌드해 보지 않았다 |
| 외부 기술 | Supabase (PostgreSQL, Auth — 이메일 · 비밀번호 로그인, GitHub 계정 연동. - **검증됨** — 정해진 입력 세트로 돌려 결과를 확인했다. 방법과 숫자를 적는다 (예: "샘플 30건 중 26건 정답").

- **미적용** — 계획했지만 구현하지 않았다. AI 대신 무엇이 그 일을 하는지 적는다.

## 5. 알려진 한계

발표 "실제 결과 · 오류와 한계"에 그대로 쓴다. 감추면 질의응답에서 잃는다.

- **배포 전에 코드를 검토하지 않는다(2026-11-11).** 보안 검사는 규칙 기반 도구가 하고 배포를 막지 않는다. 학생 코드의 악의적 동작은 NetworkPolicy · 쿼터 · 비루트 실행으로 피해 범위를 줄일 뿐 막지 못한다. AI 코드 검토도 큰 파일에 묻힌 악성 로직을 놓칠 수 있다는 보도가 있다 (2차 출처, 원문 확인 필요). 정확도는 우리가 직접 측정한 수치만 발표한다.
- **컨테이너 격리는 완전하지 않다.** k3s 기본 런타임은 호스트 커널을 공유한다. 기본 차단 NetworkPolicy · 쿼터 · 비루트 실행으로 보완하고, 강한 격리(gVisor 등)는 하지 않는다 (설정 방법은 미확인).
- **리더가 단일 장애점이다.** 승격은 범위 밖이다. 터널이 리더에 있어 리더가 꺼지면 방문자도 들어오지 못한다(터널을 워커로 옮기는 것은 후순위). 스위치와 벽 랜 포트(인터넷 길)도 단일 장애점이다. 정전 · 인터넷 길 끊김 · 디스크 가득 참이 흔한 실패 원인이다.
- **도메인은 구축 담당 개인 소유(`stairnoworks.com`)다.** 대회 동안만 쓰고 끝나면 와일드카드와 터널을 지운다. 방문자 트래픽은 Cloudflare를 거친다.
- **학생 DB는 학생 것이다(MVP, 2026-11-07).** 플랫폼은 학생 DB를 띄우거나 백업하지 않는다. 학생 데이터의 보존은 학생 DB 쪽 책임이다.
- **메일 인증과 비밀번호 재설정 메일은 Supabase 내장 메일 서버로 보낸다.** 팀 멤버 주소로만 가고 시간당 2통이라, 심사위원 같은 외부 사용자가 직접 가입하거나 재설정할 수 없다. 심사용 계정은 대시보드에서 직접 만들어(Auto Confirm User) 건넨다. 직접 가입이 필요해지면 Custom SMTP로 바꾼다([auth.md](design/auth.md)).
- **리더 상태 스냅샷의 클러스터 밖 백업은 후순위다.** 그것이 들어가기 전까지는 리더 디스크가 죽으면 클러스터를 다시 세워야 한다.
