# 시스템 아키텍처

학교 실습실에서 놀고 있는 PC를 묶어, 학생이 만든 프로젝트를 대신 실행해 주는 서비스의 구조와 아직 정하지 않은 사항을 정리한 문서다.

![시스템 아키텍처 구성도](system-architecture.drawio.svg)

구성도 원본은 `system-architecture.drawio.svg` 하나다. draw.io(데스크톱 또는 VS Code 확장)로 열면 바로 수정할 수 있고, 압축하지 않은 XML이 들어 있어 텍스트로도 읽을 수 있다.

## 1. 서비스 흐름 요약

1. 학생이 웹사이트에 프로젝트를 올린다.
2. API 서버가 LLM API로 코드를 분석해 실행 방식을 분류하고, 위험한 코드를 표시한다.
3. 분류 결과에 따라 다르게 처리한다.

| 실행 방식 | 처리 | 학교 PC 필요 |
| --- | --- | --- |
| 정적 | 결과 파일을 R2에 올려 바로 보여준다 | 아니오 |
| 브라우저 실행 | 빌드가 필요하면 빌드한 뒤 R2에 올려 보여준다 | 아니오 |
| 서버 필요 | 도커 이미지로 빌드해 GHCR에 올리고, 켜져 있는 학교 PC에 k3s로 배치한다 | 예 |

4. 학교 PC가 전부 꺼져 있으면 서버 필요 프로젝트는 R2에 저장해 둔 정적 미리보기만 보여준다.

## 2. 영역과 구성 요소

기술 이름은 아직 확정 전이다. 구성도에서 아이콘과 이름 라벨을 따로 두었으므로 바뀌면 해당 상자만 고치면 된다.

| 영역 | 구성 요소 | 역할 |
| --- | --- | --- |
| 개발 영역 | 개발자 (팀원 3명) | 코드 작성, PR |
| | GitHub | 모노레포 `WOOWANGTHON_TEAM_18` (`frontend/`, `backend/`, `ai/`) |
| | GitHub Actions | 테스트, 빌드, 배포 |
| | GHCR | 학생 프로젝트 컨테이너 이미지 저장소 |
| Vercel | 프론트엔드 (React) | 우리 서비스 웹사이트 |
| 클라우드 VM – Main (항상 켜짐) | Nginx | 요청 분배 (API 서버, 학교 PC의 학생 프로젝트) |
| | API 서버 (FastAPI) | 업로드 처리, 코드 분석 요청, 학교 PC 켜짐 여부 판단 |
| | 빌드 작업기 | 학생 코드를 도커 이미지로 빌드 |
| | k3s 서버 | 쿠버네티스 관리자, 학생 프로젝트를 학교 PC에 배치 |
| 외부 서비스 | PostgreSQL (Supabase) | 사용자, 프로젝트, 실행 기록 |
| | LLM API | 코드 분석, 실행 방식 분류, 위험 코드 표시 |
| | Cloudflare R2 | 학생 프로젝트의 정적 빌드 파일, 미리보기 |
| Tailscale 사설망 | — | 클라우드 VM과 학교 PC를 잇는 유일한 통로 (학교 PC는 학교 방화벽 안에 있음) |
| 학교 실습실 PC (켜져 있을 때만 참여) | k3s 에이전트 | k3s 서버의 지시를 받아 컨테이너 실행, 켜짐 상태 보고 |
| | 학생 프로젝트 컨테이너 | 서버가 필요한 학생 프로젝트 |

### Vercel과 R2의 차이

둘 다 정적 파일을 내보내지만 대상이 다르다.

- **Vercel**: 우리 팀이 만든 서비스 웹사이트(React)만 올린다. `frontend/`가 main에 머지되면 빌드해서 Vercel CDN에 배포한다. 학생 코드는 들어가지 않는다.
- **R2**: 학생 프로젝트 결과물을 넣는 파일 저장소다. 정적·브라우저 실행 프로젝트의 빌드 결과와, 서버 필요 프로젝트의 미리보기를 둔다. S3 호환 API라 FastAPI에서 `boto3`로 올릴 수 있고, 외부 전송(egress) 요금이 없다.

### 학교 PC 한 대에 여러 프로젝트

구성도는 단순하게 PC마다 학생 프로젝트 컨테이너를 하나씩 그렸지만, 실제로는 PC 한 대에 여러 개가 돈다. 학생 프로젝트 하나가 Pod 하나이고, k3s 서버가 각 PC의 남은 CPU·메모리를 보고 자리가 있는 PC에 배치한다. 작은 웹 서버는 128~512MB면 충분하므로, 16GB PC에서 학생 몫을 10GB로 잡으면 한 대에 20~40개가 들어간다.

## 3. 흐름 (구성도 색 기준)

| 색 | 흐름 | 경로 |
| --- | --- | --- |
| 검정 | 사용자 요청 | 브라우저 → 프론트엔드(Vercel) / 브라우저 → Nginx → API 서버 / Nginx → (Tailscale) → 학교 PC의 학생 프로젝트 |
| 파랑 | 코드 배포 (CI/CD) | 개발자 → GitHub → GitHub Actions → 프론트엔드(Vercel), 클라우드 VM |
| 주황 | AI 분석 | API 서버 ↔ LLM API |
| 초록 | 학생 프로젝트 실행 | API 서버 → 빌드 작업기 → GHCR(이미지 올림) / API 서버 → k3s 서버 → (Tailscale) → 학교 PC / 학교 PC → GHCR(이미지 받음) |
| 보라 | 데이터 | API 서버 ↔ PostgreSQL / API 서버 → R2 / 프론트엔드 → R2 (PC가 꺼졌을 때 미리보기) |
| 회색 점선 | 상태 확인 | 학교 PC → k3s 서버 (켜짐 여부 보고) |

## 5. 정해야 할 것

| # | 항목 | 고민할 점 | 제안 |
| --- | --- | --- | --- |
| 1 | 모노레포 폴더 이름 | `frontend/backend/ai`인지 `fe/be/ai`인지. 정해진 뒤에 뼈대를 만든다 | `frontend/`, `backend/`, `ai/` |
| 2 | "정적 미리보기"의 정의 | 서버 필요 프로젝트의 미리보기가 화면 스크린샷인지, 백엔드 없이 프론트만 띄운 것인지. 스크린샷이면 누가 언제 찍는지 | 정해지면 구성도에 반영 |
| 3 | R2에 올리는 주체 | 지금 구성도에는 API 서버 → R2만 있다. 빌드가 필요한 정적 프로젝트는 빌드 작업기가 결과물을 올려야 한다 | 빌드 작업기 → R2 흐름 추가 |
| 4 | 학생 결과물 도메인 분리 | 학생 코드를 서비스와 같은 도메인에서 띄우면 학생 JS가 서비스 쿠키·세션에 접근할 수 있다 | 서비스(`app.example.com`)와 학생 결과물(`example-usercontent.com`) 도메인을 분리 |
| 5 | PC 사용자 몫 예약 | 수업 중에는 사람이 PC를 쓴다. 학생 프로젝트가 PC를 느리게 만들면 학교가 참여를 막을 수 있다 | k3s 에이전트에 `--kubelet-arg=system-reserved=...`로 CPU·메모리를 미리 떼어 둔다 |
| 6 | Pod 자원 기본값 | requests/limits가 없으면 무한루프 하나가 같은 PC의 다른 프로젝트까지 죽인다 | 모든 Pod에 requests/limits 필수, 기본값은 측정 후 결정 |
| 7 | 안 쓰는 프로젝트 내리기 | 아무도 보지 않는 프로젝트를 계속 켜 두면 자원 낭비다 | 마지막 접속 후 30분이 지나면 API 서버가 내리고, 다시 접속하면 띄운다 (재시작에 몇 초 걸림) |
| 8 | 격리 수준 | 한 PC에 서로 다른 학생의 코드가 같이 돈다. 컨테이너는 커널을 공유하므로 완전한 격리는 아니다 | root가 아닌 사용자로 실행, NetworkPolicy로 Pod 간 통신 차단, 호스트 폴더 마운트 금지. 이후 gVisor 같은 샌드박스 런타임으로 확장 가능 |
| 9 | 위험 코드 처리 | LLM이 위험 코드를 표시한 뒤 실행을 막는지, 경고만 하는지 | 팀 논의 |
| 10 | PC가 꺼질 때 실행 중인 프로젝트 | 다른 PC로 다시 배치할지, 바로 미리보기로 전환할지 | 팀 논의 |
| 11 | 학교 PC 켜짐 판단 방식 | API 서버가 무엇을 보고 켜짐을 판단하는지 | k3s 노드의 Ready 상태를 그대로 사용 |
| 12 | 도커로 돌릴 구성 요소 | 구성도에는 Nginx, FastAPI, 학생 프로젝트에만 도커 표시를 붙였다. 빌드 작업기와 k3s 서버는 미정 | 팀 논의 |
| 13 | 기술 확정 | 클라우드 VM 업체, LLM 업체, 빌드 도구(Docker, BuildKit, Kaniko 등) | 팀 논의 |

## 6. 구성도 참고

- 학교 PC 쪽 화살표는 PC마다 긋지 않고 실습실 영역 테두리에 연결했다. Nginx의 사용자 요청만 PC 1의 학생 프로젝트에 대표로 연결했다.
- draw.io 내장 라이브러리에 아이콘이 없어 회색 점선 상자로 자리만 잡아 둔 구성 요소: GitHub Actions, GHCR, React, Nginx, FastAPI, Cloudflare R2, LLM API, Tailscale.
