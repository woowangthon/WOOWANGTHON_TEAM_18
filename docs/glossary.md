# 용어 정리

[시스템 아키텍처](system-architecture.md) 문서와 구성도에 나오는 용어를 정리했다. "이 프로젝트에서" 열은 우리 서비스에서 그 용어가 가리키는 대상이다.

## 1. 서비스 개념

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| 학생 프로젝트 | 학생이 웹사이트에 올린 코드 묶음 | 우리 서비스가 대신 실행해 주는 대상 |
| 실행 방식 | 프로젝트를 띄우는 데 무엇이 필요한지에 따른 분류 | LLM 분석 결과로 정적 / 브라우저 실행 / 서버 필요 중 하나로 정한다 |
| 정적 | 서버 없이 HTML·CSS·이미지 파일만 내려주면 되는 프로젝트 | R2에 올려 바로 보여준다 |
| 브라우저 실행 | 서버는 필요 없지만 JS가 브라우저에서 동작하는 프로젝트. 빌드가 필요할 수 있다 (예: React 앱) | 빌드 결과를 R2에 올려 보여준다 |
| 서버 필요 | 실행 중인 서버 프로세스가 있어야 동작하는 프로젝트 (예: Flask, Express) | 도커 이미지로 빌드해 학교 PC에서 실행한다 |
| 정적 미리보기 | 서버 필요 프로젝트를 실행할 수 없을 때 대신 보여주는 정적 화면 | 학교 PC가 전부 꺼졌을 때 R2에서 보여준다. 정확한 형태는 미정 |
| 위험 코드 표시 | 파일 삭제, 무한 자원 사용, 외부 공격 같은 위험한 코드를 찾아 표시하는 것 | LLM 분석 단계에서 한다. 표시 후 처리 방식은 미정 |
| 켜짐 여부 | 학교 PC가 지금 프로젝트를 받을 수 있는 상태인지 | k3s 에이전트가 보고하고 API 서버가 판단한다 |

## 2. 개발·협업

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| 레포 (저장소) | Git으로 관리하는 코드 저장 공간 | `woowangthon/WOOWANGTHON_TEAM_18` |
| 모노레포 | 여러 부분(프론트·백엔드 등)을 레포 하나에 폴더로 나눠 두는 방식 | 레포 하나에 `frontend/`, `backend/`, `ai/` |
| 포크 (fork) | 남의 레포를 내 계정으로 복사한 것. 원본과 자동으로 동기화되지 않는다 | 팀원 각자 포크에서 작업한다 |
| origin / upstream | 내 로컬 레포가 가리키는 원격 이름. 보통 origin은 내 포크, upstream은 원본 | 원본 최신 내용은 `git pull upstream main`으로 받는다 |
| 브랜치 | 작업을 main과 분리해 진행하는 갈래 | 기능마다 브랜치를 만든다 |
| PR (Pull Request) | 내 브랜치의 변경을 다른 브랜치에 합쳐 달라는 요청. 리뷰를 거친다 | 포크 브랜치 → 원본 main |
| CI/CD | 지속적 통합(테스트·빌드 자동화) / 지속적 배포(자동 배포) | GitHub Actions가 맡는다 |
| GitHub Actions | GitHub에서 이벤트(푸시, PR 등)마다 작업을 자동으로 돌리는 기능 | 테스트, 빌드, Vercel·클라우드 VM 배포 |
| 경로 필터 | 특정 폴더가 바뀌었을 때만 워크플로를 돌리는 설정 (`paths:`) | `frontend/`가 바뀌면 프론트만 빌드·배포 |

## 3. 컨테이너·쿠버네티스

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| 도커 (Docker) | 프로그램과 실행 환경을 묶어 어디서나 똑같이 실행하게 해 주는 도구 | 학생 프로젝트를 이미지로 만든다 |
| 이미지 | 프로그램과 실행 환경을 묶은 실행 전 상태의 꾸러미 | 빌드 작업기가 학생 코드로 만든다 |
| 컨테이너 | 이미지를 실제로 실행한 것. 다른 컨테이너와 분리된 공간에서 돈다 | 학교 PC에서 도는 학생 프로젝트 |
| 레지스트리 | 이미지를 올리고 받는 저장소 | GHCR |
| GHCR | GitHub Container Registry. GitHub이 제공하는 레지스트리 | 빌드 작업기가 올리고 학교 PC가 받는다 |
| 쿠버네티스 (Kubernetes, k8s) | 여러 컴퓨터에 컨테이너를 나눠 배치하고 관리하는 시스템 | 학교 PC 여러 대를 묶는 데 쓴다 |
| k3s | 가벼운 쿠버네티스 배포판. 설치가 간단하고 자원을 적게 쓴다 | 클라우드 VM과 학교 PC에 설치한다 |
| 클러스터 | 쿠버네티스로 묶인 컴퓨터 전체 | 클라우드 VM + 켜져 있는 학교 PC |
| 노드 | 클러스터에 속한 컴퓨터 한 대 | 학교 PC 한 대가 노드 하나 |
| k3s 서버 (컨트롤 플레인) | 클러스터를 관리하는 쪽. 어디에 무엇을 띄울지 정한다 | 클라우드 VM에서 돈다 |
| k3s 에이전트 | 서버의 지시를 받아 실제로 컨테이너를 실행하는 쪽 | 학교 PC마다 하나씩 돈다 |
| Pod | 쿠버네티스가 배치하는 최소 단위. 컨테이너 하나 이상을 감싼다 | 학생 프로젝트 하나 = Pod 하나 |
| 스케줄링 | 어느 노드에 Pod를 띄울지 정하는 것 | k3s 서버가 PC별 남은 자원을 보고 정한다 |
| requests / limits | Pod가 최소로 필요한 자원 / 최대로 쓸 수 있는 자원 | 모든 학생 Pod에 필수로 건다 |
| system-reserved | 노드에서 쿠버네티스가 쓰지 못하게 미리 떼어 두는 자원 | 수업 중 PC를 쓰는 사람 몫을 남긴다 |
| Ready 상태 | 노드가 정상이라 Pod를 받을 수 있다는 쿠버네티스 상태 값 | 학교 PC 켜짐 판단 기준 후보 |
| NetworkPolicy | Pod끼리 또는 Pod와 외부 사이의 통신을 허용·차단하는 규칙 | 학생 Pod끼리 서로 통신하지 못하게 막는다 |
| 샌드박스 런타임 | 컨테이너를 일반 컨테이너보다 강하게 격리해 실행하는 런타임 (예: gVisor) | 이후 보안 강화 방안 |
| 유휴 종료 (scale to zero) | 사용하지 않는 프로젝트를 내렸다가 요청이 오면 다시 띄우는 것 | 마지막 접속 후 일정 시간이 지나면 내린다 (기준 미정) |

## 4. 서버·네트워크

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| 클라우드 VM | 클라우드 업체에서 빌린 가상 서버 | 항상 켜져 있는 메인 서버 (업체 미정) |
| Nginx | 웹 서버. 들어온 요청을 알맞은 곳으로 넘기는 리버스 프록시로 쓴다 | API 서버, 학교 PC의 학생 프로젝트로 요청을 나눈다 |
| 리버스 프록시 | 사용자 요청을 대신 받아 뒤쪽 서버로 전달하는 서버 | Nginx의 역할 |
| API 서버 | 프론트엔드가 호출하는 백엔드 서버 | FastAPI로 만든다 |
| FastAPI | 파이썬 웹 프레임워크 | API 서버 |
| 빌드 작업기 | 학생 코드를 실행 가능한 형태(이미지, 정적 파일)로 만드는 프로세스 | 클라우드 VM에서 돈다 |
| 방화벽 | 허용하지 않은 네트워크 연결을 막는 장치·설정 | 학교 PC는 학교 방화벽 안에 있어 밖에서 바로 접속할 수 없다 |
| Tailscale | 여러 기기를 하나의 사설망으로 묶어 주는 VPN 서비스. 방화벽 안쪽 기기도 연결할 수 있다 | 클라우드 VM과 학교 PC를 잇는 유일한 통로 |
| 사설망 | 외부에서는 보이지 않고 참여한 기기끼리만 통신하는 네트워크 | Tailscale로 만든 망 |

## 5. 배포·저장소·외부 서비스

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| Vercel | 프론트엔드를 빌드해 배포해 주는 호스팅 서비스 | 우리 서비스 웹사이트(React)만 올린다 |
| React | 웹 화면을 만드는 JS 라이브러리 | 프론트엔드 |
| CDN | 파일을 전 세계 여러 서버에 복사해 두고 가까운 곳에서 내려주는 네트워크 | Vercel, Cloudflare가 제공한다 |
| 오브젝트 스토리지 | 파일을 폴더 구조 대신 키로 저장하는 저장소 (예: AWS S3) | Cloudflare R2 |
| Cloudflare R2 | Cloudflare의 오브젝트 스토리지. S3와 같은 방식으로 쓸 수 있다 | 학생 프로젝트 정적 파일, 미리보기 |
| S3 호환 | AWS S3와 같은 API로 쓸 수 있다는 뜻. S3용 도구를 그대로 쓸 수 있다 | FastAPI에서 `boto3`로 R2에 올린다 |
| egress | 저장소에서 밖으로 나가는 데이터 전송. 보통 요금이 붙는다 | R2는 egress 요금이 없다 |
| PostgreSQL | 관계형 데이터베이스 | 사용자, 프로젝트, 실행 기록 |
| Supabase | PostgreSQL을 관리형으로 제공하는 서비스 | DB 호스팅 |
| LLM API | 대형 언어 모델을 호출하는 API | 코드 분석, 실행 방식 분류, 위험 코드 표시 (업체 미정) |

## 6. 보안

| 용어 | 뜻 | 이 프로젝트에서 |
| --- | --- | --- |
| 신뢰할 수 없는 코드 | 작성자를 믿을 수 없어 악의적일 수 있다고 가정하는 코드 | 학생이 올린 모든 코드 |
| 격리 | 한 프로그램이 다른 프로그램이나 호스트에 영향을 주지 못하게 분리하는 것 | 컨테이너, NetworkPolicy, 자원 제한으로 한다 |
| non-root 실행 | 관리자 권한이 없는 사용자로 프로그램을 실행하는 것 | 학생 컨테이너는 모두 non-root로 실행 |
| 도메인 분리 | 서비스와 사용자 업로드 콘텐츠를 서로 다른 도메인에서 제공하는 것. 업로드 코드가 서비스 쿠키·세션에 접근하지 못한다 | 학생 결과물 전용 도메인을 따로 둔다 (GitHub의 `githubusercontent.com`과 같은 방식) |
| 쿠키 / 세션 | 로그인 상태를 기억하기 위해 브라우저와 서버가 주고받는 정보 | 도메인 분리로 보호한다 |
