# ADR-008: 노드망은 학교 유선망과 같은 선에 두고, 출발지 주소로 거르는 방화벽으로 나눈다

- **상태**: 유효
- **날짜**: 26-11-06
- **결정자**: 유성 (클러스터 구성, 구축 담당)
- **관련**: [시스템 정의서 §5.1](../system-definition.md#51-물리--네트워크), [클러스터 설계](../design/cluster.md) §2 · §3, [ADR-004](004-server-cluster-link-tailscale.md)
- **대체**: ADR-005의 노드망 항목("노드끼리는 우리 장비로 직접 이어 학교망과 분리한다")

## 맥락

[ADR-005](005-k3s-cluster-on-school-pcs.md)는 노드끼리를 우리 스위치로 묶어 학교망과 분리하고, 인터넷은 노드마다 학교 와이파이로 나간다고 전제했다. PC를 받아 보니(2026-11-03 ~ 05) 세 대 모두 와이파이 카드가 없고, 동아리방 벽 랜 포트가 학교가 준 고정 주소 그대로 인터넷을 준다. 인터넷 길이 그 벽 포트 하나뿐이라, 우리 스위치에 벽 포트를 물려 같은 선으로 인터넷과 노드끼리 연결을 함께 쓰게 됐다. 그래서 노드망은 물리적으로 학교망과 분리되지 않는다.

## 결정

노드끼리는 같은 스위치(학교 유선망과 같은 선)에서 각 노드 랜 카드에 두 번째로 얹은 노드 주소(`192.168.77.0/24`, 게이트웨이 없음)로 통신하고, k3s는 이 주소만 쓴다. 분리는 호스트 방화벽이 맡는다: 들어오는 연결을 기본 거부하고 **출발지 주소**가 노드 대역 · 클러스터 대역인 것과 사설망 인터페이스만 허용한다(인터페이스 단위로 열면 같은 선의 학교망 기기도 통과하기 때문이다). 원격 접속은 키로만 받는다. 값은 [클러스터 설계](../design/cluster.md) §2 · §3에 둔다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 랜 카드를 하나 더 달아 노드망을 물리적으로 분리 | 학교망 기기가 노드망에 아예 닿지 않는다 | USB 랜 어댑터와 포트가 PC마다 더 필요하고, 인터넷 길(벽 포트)은 어차피 같은 스위치를 탄다 |
| 학교 주소로 k3s를 묶기 | 설정이 가장 적다 | 학교 주소가 바뀌는 날 노드끼리 끊긴다. 방화벽을 학교 대역 전체에 열어야 한다 |
| 노드마다 와이파이로 인터넷 (ADR-005의 전제) | 노드망이 물리적으로 분리된다 | 와이파이 카드가 없다 |

## 결과

- 쉬워지는 것: 장비를 더 사지 않고, 인터넷과 노드끼리 연결이 같은 유선이라 빠르다(노드 사이 약 941Mbit/s, 2026-11-06).
- 어려워지는 것: 유선에는 클라이언트 격리가 없어 같은 선의 학교망 기기가 노드에 바로 닿는다. 막는 것은 방화벽 하나라, 방화벽 규칙이 빠지거나 꺼지면 노드의 포트가 학교망에 열린다. k3s의 Pod 네트워크도 노드 주소를 쓰게 지정해야 한다(학교 주소를 잡으면 방화벽이 막는다). 스위치와 벽 포트가 단일 장애점이 된다.
- 다시 볼 조건: 학교가 벽 포트 정책(인증 · 기기 수 제한)을 바꿀 때, 노드망을 학교망에서 물리적으로 떼어야 할 보안 요구가 생길 때.
