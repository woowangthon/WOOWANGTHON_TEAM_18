# ADR-003: 학생 앱 이미지 레지스트리는 GHCR로 두고 이미지를 공개한다

- **상태**: 유효
- **날짜**: 26-11-01
- **결정자**: 태진, 유성
- **관련**: [시스템 정의서 §3](../system-definition.md#3-시스템-개요)(컨테이너 레지스트리 행), [ADR-002](002-bot-account-for-fix-prs.md)
- **대체**: ADR-001의 레지스트리 항목

## 맥락

[ADR-001](001-stack-and-deployment.md)은 빌드 · 레지스트리 · 스토리지를 AWS로 묶으면서 레지스트리를 ECR로 적었다. 10/29 회의는 AWS를 쓰기로 했을 뿐 레지스트리를 따로 고르지는 않았다.

이미지를 받는 쪽은 학교 PC 3대의 k3s다. 노드 앞에 사람이 늘 있지 않으므로 기준을 "노드에 만료되는 자격증명을 두지 않는다"로 잡았다. 비공개 ECR은 pull 토큰이 12시간마다 만료되어, 리더에 토큰 갱신 잡과 AWS 자격증명이 올라가야 한다. 11/01 디스코드에서 GHCR 공개와 ECR Public을 놓고 GHCR로 합의했다.

## 결정

학생 앱 이미지는 GHCR에 공개로 올린다. 노드는 토큰 없이 받는다. 빌드는 ADR-001대로 CodeBuild가 하고, 봇 계정 토큰(`write:packages`)으로 push한다. 이 토큰은 빌드 쪽에만 둔다. GHCR은 처음 push한 패키지를 비공개로 만들므로, 첫 push 뒤 패키지를 공개로 바꾸고 토큰 없이 pull되는지 확인한다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 비공개 ECR (ADR-001) | AWS 안에서 끝나고 IAM으로 권한을 관리한다 | pull 토큰이 12시간마다 만료되어 노드에 갱신 잡과 AWS 자격증명이 올라간다 |
| ECR Public | 토큰 없이 pull하고, push 권한은 IAM 그대로 | 둘 중 편한 쪽으로 정하기로 했고, 봇 계정(ADR-002)이 이미 GitHub에 있어 push 자격증명을 한곳에서 관리하는 GHCR로 정했다 |
| 비공개 GHCR | 이미지가 공개되지 않는다 | 무료 한도(저장 500MB, 전송 월 1GB, Actions 아티팩트와 합산)가 학생 앱 이미지(보통 150~400MB) 두세 개면 끝난다 |
| Docker Hub | 널리 쓰인다 | 익명 pull 횟수 제한이 있고 계정을 하나 더 관리해야 한다. 바꿀 일이 생길 때의 후보로 둔다 |

## 결과

- 쉬워지는 것: 학교 PC에 레지스트리 자격증명과 AWS 자격증명이 올라가지 않는다.
- 어려워지는 것: 학생 코드가 이미지 안에서 공개된다(레포가 이미 공개라 감수한다). 빌드(AWS)와 레지스트리(GitHub)가 갈라져 push 토큰을 CodeBuild 쪽에서 관리해야 한다.
- 다시 볼 조건: 비공개 레포를 받게 될 때, GHCR의 공개 이미지 정책이나 한도가 바뀔 때.
