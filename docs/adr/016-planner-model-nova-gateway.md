# ADR-016: AI 에이전트의 planning 외부 모델은 충북대 NOVA API Gateway의 gpt-6.1-sol이다

- **상태**: 유효 (일부 대체: 로컬 모델과 나누는 방식 → 017)
- **날짜**: 2026-11-13
- **결정자**: 사용자 결정(2026-11-13)
- **관련**: SRS `FR-075` · `FR-098` · `FR-102`, [ADR-001](001-stack-and-deployment.md)(LLM 업체 · 모델은 정하지 않았던 항목), [ADR-012](012-agent-acts-through-platform-gateway.md), [AI 에이전트 설계](../design/AIagent.md) §9, [`ai-scope.md`](../ai-scope.md)

## 맥락

배포 실패를 고치는 AI 에이전트는 자주 부르는 일(분류 · 도구 고르기 · playbook)을 리더의 로컬 모델(Qwen3-8B)로 하고, playbook이 실패했거나 모르는 실패일 때만 외부 추론 모델로 계획한다(④ · ⑤). 코드는 OpenAI 호환 주소 · 모델 이름 · 키를 env(`PLANNER_MODEL_*`)로 받게 만들어 두었지만, 업체 · 모델이 정해지지 않아 문서는 "미정"이었다. EC2에 AI 서버를 올리면서 실제 모델을 정해야 했다. 마감(2026-11-15)이 가까워 새 계약 · 결제 없이 바로 쓸 수 있는 길이 필요했다.

## 결정

planning 외부 모델은 충북대 생성형 AI 플랫폼 NOVA의 API Gateway가 제공하는 `gpt-6.1-sol`이다. OpenAI 호환 Chat Completions이고 도구 호출(`tools` · `tool_choice`)을 지원해, 코드를 바꾸지 않고 env만으로 붙인다(주소 `https://factchat-cloud.mindlogic.ai/v1/gateway`, mindlogic이 운영하는 게이트웨이를 거쳐 업체로 간다). 키는 SSM `/wcp/ai/PLANNER_MODEL_API_KEY`에 두고 레포 · 문서에 쓰지 않는다. 로컬 모델(리더 vLLM `qwen3-8b-awq`)과 나누는 방식은 그대로다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 같은 게이트웨이의 GPT-6.1 Terra | 더 싸다 | 에이전트 도구 사용 벤치마크(Terminal-Bench 4.0 약 50%)가 sol(약 55%)보다 낮다. planning은 playbook 실패 · 모르는 실패일 때만 불려 비용 차이가 작다 |
| 외부 모델 없이 로컬 모델만 | 데이터가 밖으로 나가지 않는다. 비용이 없다 | 8B 모델의 계획 품질이 모르는 실패를 풀기에 부족하다. 로컬만으로 도는 길은 외부 API를 못 쓸 때의 대체로 남긴다 |

## 결과

- 쉬워지는 것: 새 계약 · 결제 없이 OpenAI 호환 주소로 바로 붙는다. 코드 변경 없이 env만 바꾼다.
- 어려워지는 것: planning 요청의 문제 요약 · 로그 조각이 학교 게이트웨이(mindlogic)와 모델 업체로 나간다. 보내기 직전 가림 필터(FR-102)가 비밀값처럼 보이는 문자열을 가리지만, 정규식 · 이름 규칙이라 놓치는 모양이 있을 수 있다. 게이트웨이의 사용량 · 보관 정책은 학교 플랫폼을 따른다.
- 확인한 것: EC2의 AI 서버에 설정을 넣어 서버가 떴다(2026-11-13). 실제 티켓으로 이 모델이 불리고 도구를 호출하는지, 토큰 수 · 비용은 아직 확인하지 않았다.
- 다시 볼 조건: 게이트웨이를 쓸 수 없게 될 때(학교 계정 · 정책 변경), 도구 호출 품질이 실제 티켓에서 부족할 때, 비용이 예상보다 클 때.
