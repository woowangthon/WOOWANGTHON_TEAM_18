# ADR-010: 접수부터 빌드 요청까지와 보안 검사는 플랫폼 서버(Nest)가 한다

- **상태**: 유효
- **날짜**: 26-11-09
- **결정자**: 팀 회의 (2026-11-09)
- **관련**: [시스템 정의서 §3](../system-definition.md#3-시스템-개요)(플랫폼 서버 · AI 서버 행) · [§4.1](../system-definition.md#41-user1-배포자-흐름), [ADR-001](001-stack-and-deployment.md), [ADR-009](009-deploy-runs-on-leader-gocd-agent.md)
- **대체**: ADR-001의 AI 서버 역할 중 "배포 전 검토"의 레포 분석 · 보안 검사

## 맥락

ADR-001은 배포 전 검토를 AI 서버(FastAPI)에 두었고, BE와 AI를 한 서비스로 묶지 않은 이유 하나로 "학생 코드를 읽는 부분을 BE와 분리하고 싶다"를 들었다. AI 담당이 낸 배포 워크플로우 설계(v15)에서 접수 · 분석 · 배포 설정 · 비밀값 받기 · 빌드까지(W0~W4)는 규칙과 코드로 처리하고, LLM은 README 문장 해석과 문제 해결 에이전트에만 쓴다. 2026-11-09 회의에서 이 앞 단계와 보안 검사를 플랫폼 서버가 맡기로 정했다.

## 결정

- 플랫폼 서버가 접수부터 빌드 요청까지(W0~W4)를 한다: 레포 소유 확인, 레포 설정 파일(package.json 등)로 프레임워크 · 진입점 · 포트를 판별해 배포 설정 초안 채우기, 학생 비밀값 받기, 빌드 요청.
- 보안 검사(비밀값 · 의존성 취약점 · 위험 패턴, 결정적 도구)도 플랫폼 서버가 돌린다. 결과 설명은 AI 서버가 한다.
- 판별은 규칙 코드이고 LLM을 쓰지 않는다. 학생 코드는 읽기만 하고 실행하지 않는다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 지금처럼 AI 서버가 분석 · 보안 검사 (ADR-001) | 학생 레포를 읽는 곳이 AI 서버 하나다 | 앞 단계가 거의 규칙 코드라 LLM 서버를 거칠 이유가 적고, 상태 · 비밀값 · 빌드 요청을 가진 플랫폼 서버와 AI 서버가 단계마다 오가야 한다 |
| 분석 · 보안 검사를 빌드 단계(CodeBuild)에서 | 학생 코드를 다루는 곳이 격리된 빌드 하나로 모인다 | 빌드 전에 학생에게 보여 줄 배포 설정 초안이 늦게 나온다 |

## 결과

- 쉬워지는 것: 배포 설정 초안이 제출 직후 나온다. 상태 · 비밀값 · 빌드 요청이 한 서버 안에서 이어진다.
- 어려워지는 것: ADR-001이 피하려던 대로 학생 레포 내용이 플랫폼 서버에 들어온다. 레포는 임시 디렉터리에 읽기 전용으로 받고 끝나면 지우며, 실행하지 않는다. 스캐너는 시간 · 크기 상한을 걸고, 레포의 README · 주석은 신뢰하지 않는 데이터로 다룬다. 플랫폼 서버에 스캐너 도구가 깔린다.
- 다시 볼 조건: 학생 레포 내용으로 플랫폼 서버가 영향을 받는 문제가 생길 때, 보안 검사 시간이 접수 응답을 막을 만큼 길어질 때.

## 정정 (2026-11-15)

코드·설정과 대조해 사실이 달라진 곳만 적는다. 결정 자체는 바꾸지 않는다.

- 결정의 "프레임워크 · 진입점 · 포트를 판별"은 지금 Vite + React와 Next.js의 프레임워크 · 언어 · 패키지 매니저 · 명령 · 출력 폴더 · 포트 기본값까지다. 진입점 · 환경변수 이름 · 백엔드 프레임워크(Nest 등)는 판별하지 않고, 모르면 "판단 필요"로 두어 학생이 고친다(`BE/src/repos/deploy-spec.ts`, [`ai-scope.md`](../ai-scope.md) FR-022).
- 결정의 보안 검사는 비밀값 · `.env` 파일 · 의존성 취약점까지다(`BE/src/security/`, 결과 종류 `secret` · `env_file` · `vuln`). "위험 패턴" 검사는 두지 않았고, "결과 설명은 AI 서버가 한다"도 구현하지 않았다. 검사 결과는 배포를 막지 않는 경고로 붙는다.
