# ADR-004: 플랫폼 서버는 Tailscale 사설망으로 리더의 쿠버네티스 API를 직접 부른다

- **상태**: 유효
- **날짜**: 26-11-01
- **결정자**: 태진, 유성
- **관련**: [시스템 정의서 §3](../system-definition.md#3-시스템-개요)(사설망 행), [ADR-001](001-stack-and-deployment.md)(플랫폼 서버는 AWS)

## 맥락

플랫폼 서버(AWS 상시 실행)가 학교 PC 3대의 k3s 리더에 배포 · 조치를 지시하고 상태 · 지표를 읽어야 한다. 학교에는 들어오는 포트를 열지 않으므로 연결은 학교 안에서 밖으로 걸어야 한다. PR 8 시점의 설계는 리더 에이전트가 서버로 WebSocket을 걸어 두고 그 연결로 지시를 받는 방식이었다. 한편 운영자가 세 PC에 원격으로 들어가기 위해 세 노드에 Tailscale을 깔기로 이미 정했다. 11/01 디스코드에서 합의했다.

## 결정

플랫폼 서버를 같은 Tailscale 사설망에 넣고, 리더의 쿠버네티스 API를 공식 클라이언트로 직접 부른다. 지표(Prometheus)도 같은 길로 조회한다. 서버 계정은 학생 프로젝트 공간 안의 자원만 쓰도록 권한과 검사 규칙으로 좁히고, 사설망 접근 규칙으로 서버는 리더 API에만 닿게 한다. 서버의 쿠버네티스 호출은 모듈 하나로 분리해, 나중에 에이전트 방식으로 바꿀 때 그 모듈만 갈아 끼운다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 리더 에이전트 + WebSocket (PR 8 설계) | 나가는 443 하나로 일반 웹 트래픽과 같다. 클러스터 권한이 클러스터 안에만 있다 | 에이전트 · 게이트웨이 · 메시지 형식 · 인증 · 재연결을 새로 짜야 한다. 후순위 확장안으로 둔다 |
| 리더 API를 공개 포트로 연다 | 구성이 가장 단순하다 | 학교에 들어오는 포트를 열어야 하고, 쿠버네티스 API가 인터넷에 노출된다 |

## 결과

- 쉬워지는 것: 새로 짤 코드가 거의 없다(공식 쿠버네티스 클라이언트). 지표 조회에 포트가 늘지 않는다.
- 어려워지는 것: 서버가 클러스터 접속 정보를 가진다(권한을 좁혀 보완한다). 학교망이 직접 연결을 막으면 Tailscale 중계로 돌아 느려진다. 클러스터가 늘면 서버가 접속 정보를 클러스터 수만큼 관리한다.
- 다시 볼 조건: 중계 지연이 배포 · 조회에 문제가 될 때, 클러스터가 여럿이 될 때.
