# ADR — 아키텍처 결정 기록

**되돌리기 비싼 결정만** 남긴다: 스택, 데이터 저장소, AI 모델·외부 API, FE/BE/AI 경계, 배포처.
라이브러리 하나, 폴더 이름 같은 건 ADR 감이 아니다 — 커밋 메시지로 충분하다.

## 규칙

- **회의에서 정한 뒤에 쓴다.** ADR은 제안서가 아니라 기록이다. PR이 머지되면 확정이고, '제안' 단계는 없다. 아직 정하지 못했다면 [`SRS.md`](../SRS.md) §7 열린 질문에 둔다.
- [`000-template.md`](000-template.md)를 복사해 `NNN-<slug>.md`로 만든다. 번호는 다음 숫자. 번호가 겹치면 나중에 머지되는 PR이 rebase할 때 바꾼다.
- **1페이지.** 대안을 최소 하나 적는다. 대안이 없었다면 결정이 아니라 사실이다.
- 상태는 두 가지다: `유효`, `대체됨 (→ NNN)`.
- **결정이 바뀌면** 선행 ADR을 지우지 않는다. 같은 PR에서 ① 새 ADR을 쓰고(`대체` 줄에 선행 번호, 맥락에 무엇이 왜 바뀌었는지) ② 선행 ADR은 **상태 줄만** `대체됨 (→ NNN)`으로 바꾼다. 본문은 고치지 않는다 (오탈자 제외). 일부만 바뀌어도 새 ADR로 대체하고, 유지되는 부분은 새 ADR에 다시 적는다.
- 색인 표는 없다. 디렉터리 목록이 색인이고, 지금 유효한지는 각 파일 첫머리의 상태로 본다.
- [`SRS.md`](../SRS.md) §2나 [`design/`](../design/README.md)에 영향이 있으면 같은 PR에서 고친다.
- 심사 Q&A의 "왜 이 기술을 썼나요?"에 대한 답이 여기 있다. 발표 전 한 번 훑는다.

## 스택 ADR을 쓸 때 같은 PR에서 할 일

- [`CLAUDE.md`](../../CLAUDE.md) Commands 블록 채우기 (설치, 실행, lint, 테스트, 뮤테이션 테스트, 빌드). 테스트 라이브러리와 뮤테이션 도구도 스택과 함께 정하고, [`conventions.md`](../conventions.md) §6을 채운다.
- [`system-definition.md`](../system-definition.md) §3 구성요소 표와 §6 갱신 ([`SRS.md`](../SRS.md) §2는 이 문서를 가리키는 포인터로 둔다)
- [`ai-scope.md`](../ai-scope.md) 외부 기술 표에 선택한 프레임워크·모델 추가
- **CI 작성** — 빌드·테스트 job, 문서 상대 링크 검사, 코드의 `MOCK(id)`·`SAMPLE(id)` ↔ `ai-scope.md` 대조, 배포 URL 업타임 cron(심사 종료까지, [`hackathon.md`](../hackathon.md)), 제출용 `submission` 태그 + main 해시 출력 (수동 실행)
