# ADR-014: AI 에이전트의 시험은 시험 전용 파이프라인으로 하고, verified 뒤에는 고친 입력으로 배포를 처음부터 다시 실행한다

- **상태**: 유효
- **날짜**: 26-11-11
- **결정자**: 김현식
- **관련**: [AI 에이전트 설계](../design/AIagent.md) §2 · §6, [배포 워크플로우 설계](../design/deploy-workflow.md) §3 · §6, [API 계약](../design/api.md) "파이프라인 ↔ 플랫폼 서버" 4 · 5번, [ADR-011](011-deploy-slots-a-b.md), SRS UC-14 · 데모 시나리오 7단계
- **대체**: ADR-012의 시험 실행 방식(GoCD 파이프라인을 옵션으로 실행) · verified 뒤 처리(대상 슬롯 재확인 뒤 Switch와 W7)

## 맥락

ADR-012는 게이트웨이가 배포 파이프라인을 옵션(시작 스테이지, Render까지만, Switch 건너뜀)으로 실행해 시험하고, `verified`를 받으면 대상 슬롯을 다시 확인한 뒤 Switch와 W7만 실행한다고 정했다. 구현 계약을 맞추다 보니 두 가지가 문제였다. 옵션 하나만 잘못 넘어가도 시험이 공개 주소를 바꿀 수 있다. 그리고 "Switch만 실행"하려면 전환만 하는 실행 경로와 Render 산출물(`open.yaml`)을 따로 다루는 길이 하나 더 필요하다. 게이트웨이를 거쳐서만 행동한다는 것, 대상 슬롯에서 시험한다는 것, 행동 범위와 금지 범위는 그대로다.

## 결정

- 시험은 배포 파이프라인 `student-deploy`의 옵션이 아니라 **시험 전용 GoCD 파이프라인 `student-trial`**로 한다. 리더 실행기에서 Prepare → Render → Apply → Verify만 돌고 **Build · Switch 스테이지가 없다**. 시험이 공개 주소를 바꿀 길 자체를 없애고, Switch CLI도 시험 id가 있으면 거절한다.
- `verified`를 받으면 플랫폼이 고친 입력을 실행 기록에 저장하고 **`student-deploy`를 처음부터 다시 실행**한다. 모든 서비스가 이미지를 재사용하므로 Build는 CodeBuild를 부르지 않는다. 다시 실행의 Verify가 대상 슬롯 재확인이고, 통과하면 평소대로 Switch와 W7이 돈다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| `student-deploy` 하나에 옵션 env(시작 스테이지 · Switch 건너뜀) | 파이프라인이 하나다 | 옵션 실수 하나로 시험이 공개 주소를 바꾼다. 스테이지마다 옵션 분기가 늘어난다 |
| 전환 전용 파이프라인(Verify → Switch) | 다시 실행보다 빠르다 | Render 산출물을 시험에서 넘겨받는 길이 따로 필요하고, 정상 경로와 다른 전환 경로가 하나 더 생긴다 |
| 재확인 없이 Switch만 | 가장 빠르다 | 에이전트의 `verified`를 플랫폼이 확인하지 않는다(ADR-012의 재확인을 버린다) |

ADR-012가 버린 "spec 수정안만 받고 재배포"와는 다르다. 그 대안은 수정이 맞는지 재배포 뒤에야 알았다. 이번 결정은 에이전트가 시험 루프로 대상 슬롯에서 확인한 뒤에 같은 입력으로 다시 실행하는 것이다.

## 결과

- 쉬워지는 것: 시험이 공개 주소에 닿을 수 없다. 전환은 정상 배포와 같은 한 갈래(`student-deploy`의 Switch · W7)로만 일어난다. 다시 실행의 추가 비용은 AWS 실행기 준비 한 번(약 1분)과 대상 슬롯 재배포다.
- 어려워지는 것: 파이프라인 정의가 둘이다. 다시 실행이 빌드를 건너뛰려면 `build_cache`를 Build가 통과할 때 기록해야 한다. 시험과 배포가 같은 리더 실행기(1개)에 줄을 선다.
- 다시 볼 조건: 다시 실행이 데모 시간 안에 들지 않을 때, 리더 실행기를 늘릴 때.
