# ADR-009: 배포는 리더의 GoCD 실행기가 하고, GoCD 서버는 플랫폼 서버와 같은 EC2에 둔다

- **상태**: 유효 (일부 대체: 되돌리기 → [011](011-deploy-slots-a-b.md))
- **날짜**: 26-11-09
- **결정자**: 팀 회의 (2026-11-09)
- **관련**: [시스템 정의서 §3](../system-definition.md#3-시스템-개요)(배포 파이프라인 · 사설망 행), [클러스터 설계](../design/cluster.md) §8, [ADR-004](004-server-cluster-link-tailscale.md), [ADR-001](001-stack-and-deployment.md)
- **대체**: ADR-004의 배포 지시 ("플랫폼 서버가 리더의 쿠버네티스 API를 직접 불러 배포한다")

## 맥락

ADR-004는 플랫폼 서버가 사설망으로 리더의 쿠버네티스 API를 직접 불러 배포 · 조치를 지시하게 했다. 그러려면 매니페스트 생성, 적용, 롤아웃 대기, 동작 확인, 실패 때 되돌리기를 모두 서버 코드로 짜야 하고, 클러스터에 배포를 쓰는 권한이 클러스터 밖(AWS)에 놓인다. AI 담당이 낸 배포 워크플로우 설계(v15)는 배포 단계를 파이프라인으로 떼어 클러스터 안에서 돌리는 구조였고, ADR-004도 대안표에 "리더 에이전트"를 나중 확장안으로 남겨 두었다. 2026-11-09 회의에서 이 구조로 정했다.

## 결정

- 배포 단계(배포 설정과 이미지 태그로 매니페스트 만들기 → 서버 쪽 dry-run 검사 → 적용 → 롤아웃 대기 → 동작 확인 → 실패하면 직전 정상 매니페스트로 되돌리기)는 GoCD 파이프라인이 한다.
- GoCD 서버는 플랫폼 서버 · AI 서버와 같은 EC2 한 대에 둔다. 실행기(GoCD Agent)는 리더에서 돌고, 사설망(Tailscale)으로 밖에 있는 GoCD 서버에 붙어 일감을 받아 간다. 학교로 들어오는 포트는 여전히 0개다.
- 학생 비밀값(.env)은 파이프라인 · 빌드에 넘기지 않는다. 플랫폼 서버가 배포 전에 사설망으로 리더의 쿠버네티스 API에 Secret으로 넣고, 실행기는 있는지만 확인한다.
- 그 밖의 서버 → 리더 직접 호출(비밀값 쓰기, 재시작 · 중지 같은 조치, 상태 · 지표 읽기)은 ADR-004대로 둔다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 플랫폼 서버가 직접 배포 (ADR-004 그대로) | 새 구성요소가 없다 | 매니페스트 생성 · 적용 · 동작 확인 · 되돌리기를 서버 코드로 다 짜야 하고, 배포 쓰기 권한이 클러스터 밖에 있다 |
| 배포도 AWS에서 (EC2의 실행기가 사설망 너머로 적용) | 실행기가 한 곳이다 | 배포 쓰기 권한이 클러스터 밖에 남고, 동작 확인(Pod Ready · Endpoints · Ingress)을 사설망 너머에서 해야 한다 |
| ArgoCD (클러스터 안에서 git의 매니페스트를 당겨 온다) | 클러스터 안에서 끝나고 되돌리기가 내장돼 있다 | 회의 때 검토하지 않았다. AI 담당이 검토 중이다(아래 다시 볼 조건) |

## 결과

- 쉬워지는 것: 배포 단계의 로그 · 재실행 · 되돌리기를 파이프라인이 준다. 플랫폼 서버 계정의 클러스터 권한이 비밀값 쓰기 · 조치 · 읽기로 줄어든다.
- 어려워지는 것: GoCD 서버(JVM)가 플랫폼 서버와 같은 EC2에 올라가 메모리가 더 든다(8GB급). 실행기 계정의 권한과 검사 규칙을 따로 둔다([클러스터 설계](../design/cluster.md) §8). 리더가 꺼지면 배포가 멈춘다(원래도 그랬다).
- 다시 볼 조건: AI 담당의 ArgoCD 검토 결과, GoCD 서버를 플랫폼 서버와 같은 EC2에 둘 때의 문제 검토 결과(AI 담당), EC2 메모리가 모자랄 때.

## 정정 (2026-11-15)

코드·설정과 대조해 사실이 달라진 곳만 적는다. 결정 자체는 바꾸지 않는다.

- 결정의 "실행기는 있는지만 확인한다"는 지금 하지 않는다. 실행기 계정에는 Secret 읽기 권한이 없어 필요한 key가 들어갔는지 보지 못한다(`Infra/pipeline/src/prepare.ts`, [`cluster.md`](../design/cluster.md) §8). 그 확인은 플랫폼 서버가 배포를 시작할 때 DB의 key 기록으로 하고, 빠졌으면 `409 NOT_READY`로 막는다(`BE/src/deploys/deploy-readiness.service.ts`).
- 결정의 "실행기(GoCD Agent)는 리더에서 돌고"는 Build 스테이지를 뺀 나머지(Prepare · Render · Apply · Verify · Switch)에 맞다. Build는 EC2의 AWS 실행기(이름표 `aws`)가 CodeBuild를 불러 한다(`Infra/gocd/compose.yaml`, [배포 워크플로우](../design/deploy-workflow.md) §2). CodeBuild 권한이 이 실행기 컨테이너에만 있는 것은 같은 EC2에 둘 때의 조건이다.
