# ADR-002: 수정 제안은 봇 이름의 별도 GitHub 계정이 fork → PR로 올린다

- **상태**: 유효
- **날짜**: 26-10-29
- **결정자**: 태진, 유성, 현식
- **관련**: [시스템 정의서 §4.1](../system-definition.md#41-user1-배포자-흐름)(봇 PR · Dockerfile 행), [ADR-001](001-stack-and-deployment.md)

## 맥락

AI 검토 결과로 수정 제안을 하고, 수정된 파일을 PR로 올려 주는 기능은 반드시 필요하다. 레포에 `Dockerfile`이 없을 때 AI가 만든 `Dockerfile`을 같은 PR에 넣는 것도 이 경로를 쓴다. 학생 레포에는 우리에게 쓰기 권한이 없다. 진짜 GitHub App(CodeRabbit처럼)을 만들기엔 시간이 부족하다.

## 결정

- 팀원 한 명이 **봇 이름의 별도 GitHub 계정**(머신 계정)을 만들고, 그 계정의 개인 액세스 토큰(PAT)을 쓴다.
- MVP는 **공개된 학생 개인 레포만** 지원한다 (비공개 · Organization 소유 레포는 지원하지 않는다).
- PR은 **학생 레포를 봇 계정으로 fork → 브랜치에 수정 → 학생 레포로 PR** 순서로 올린다. 머지는 학생이 한다.
- 학생 로그인(Supabase GitHub OAuth)은 읽기 scope만 요청하고, 로그인한 GitHub 계정이 레포 소유자인지 대조하는 데만 쓴다. 레포가 공개가 아니거나 소유자가 로그인 계정과 다르면 제출을 거부한다 (조회 API는 구현 때 정한다).
- 토큰은 AWS 시크릿/`.env`에만 둔다 ([`CLAUDE.md`](../../CLAUDE.md) §1-4).
- 레포가 fork를 막았으면 PR 대신 리포트에 patch 텍스트를 보여 준다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| GitHub App | 권한이 레포별로 분리되고 토큰이 짧다. 이름이 `app[bot]`으로 나온다 | 학생이 설치하는 단계가 늘고 만드는 데 시간이 든다 |
| 학생 OAuth 토큰으로 학생 이름으로 PR | 봇 계정이 필요 없다 | 쓰기 scope를 받아야 하고, provider 토큰이 로그인 직후에만 얻어져 관리가 까다롭다. 학생에게 과한 권한 요청 |
| 팀원 개인 계정으로 PR | 가장 쉽다 | PR이 팀원 개인 이름으로 올라간다 |

## 결과

- 쉬워지는 것: 학생에게 추가 권한을 요구하지 않는다. 이름이 봇이라 사람이 올린 것과 구별된다.
- 어려워지는 것: 봇 계정의 PAT가 새면 그 계정이 가진 범위(fork 소유, PR 생성)가 노출된다. 봇 계정에 fork가 쌓인다. GitHub의 PR 생성 속도 제한에 걸릴 수 있다.
- GitHub 약관상 머신 계정은 사람이 책임지고 자동화 전용으로 쓰는 경우에 허용되는 범주로 알고 있다. 계정을 만들 때 약관 문구를 다시 확인한다.
- 다시 볼 조건: 사용자가 늘거나 PR 속도 제한에 걸릴 때 GitHub App으로 바꾼다.
