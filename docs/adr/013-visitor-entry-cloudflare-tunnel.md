# ADR-013: 방문자는 Cloudflare Tunnel과 stairnoworks.com의 와일드카드 주소로 학생 서비스에 들어온다

- **상태**: 유효
- **날짜**: 26-11-10
- **결정자**: 유성 (클러스터 구성, 구축 담당) · 태진, 유성 (AWS 입구 대안, 11/02 디스코드)
- **관련**: SRS NFR-OPS-01, [ADR-005](005-k3s-cluster-on-school-pcs.md), [ADR-008](008-node-network-on-school-wired-lan.md), [시스템 정의서 §4.4](../system-definition.md#44-user3-방문자-흐름) · [§6 열린 질문 5](../system-definition.md#열린-질문), [`design/cluster.md`](../design/cluster.md) §9

## 맥락

학생 서비스는 학교 PC 3대의 k3s 워커에서 돈다. 학교망에는 들어오는 포트가 없고, 우리도 학교에 포트를 열어 달라고 하지 않기로 했다(신청서는 "나가는 연결만"). 방문자가 들어오려면 클러스터가 먼저 바깥에 연결을 걸어 둬야 한다. 2026-11-06에 세 대 모두 터널 포트(TCP 7844)가 나가는 것을 확인했다.

주소는 심사가 끝날 때까지 바뀌면 안 된다(NFR-OPS-01). 시스템 정의서 §6 열린 질문 5는 도메인의 연결 범위와 구매 · 비용을 남겨 두었다. 구축 담당이 가진 `stairnoworks.com`(DNS가 이미 Cloudflare)이 있어 사지 않아도 되고, 학교 PC를 반납하면 서비스를 둘 수 없는 구조라 도메인은 대회 기간에만 필요하다.

## 결정

리더에서 Cloudflare Tunnel 클라이언트(cloudflared)를 돌리고, `*.stairnoworks.com` 와일드카드를 그 터널로 보낸다. 터널은 받은 요청을 워커의 Traefik에 넘기고, Traefik이 호스트 이름으로 프로젝트를 고른다. 학생 서비스 주소는 `<이름>.stairnoworks.com` 한 단계라 Cloudflare의 무료 인증서(와일드카드 한 단계)로 HTTPS가 된다. 플랫폼 주소는 같은 도메인의 `app`(FE) · `api`(BE)로 정하고 학생 이름에서 예약한다. 실제 레코드는 배포처가 생긴 날 붙인다.

## 대안

| 대안 | 장점 | 버린 이유 |
| --- | --- | --- |
| 학교에 포트 · 공인 IP 신청 | 터널 제공자 없이 바로 들어온다 | 처리 기간을 모르고, 학교망에 들어오는 문을 여는 것 자체가 신청서의 "나가는 연결만"과 어긋난다. 7844가 나가서 필요 없어졌다 |
| AWS 서버를 공개 입구로 두고 Tailscale로 워커 Traefik에 넘기기 (11/02 디스코드) | 터널 제공자가 하나 줄고 플랫폼과 입구가 한곳이다 | 방문자 트래픽이 모두 EC2와 중계(DERP)를 거쳐 느려지고, EC2가 꺼지면 학생 서비스도 끊긴다. 7844가 막혔을 때의 대비책으로 남긴다 |
| 학생마다 다른 도메인 · 경로(`stairnoworks.com/<이름>`) | 와일드카드가 필요 없다 | 학생 앱이 루트 경로를 가정하면 깨진다. 한 단계 하위 이름은 앱을 고치지 않아도 된다 |
| 도메인 새로 사기 | 다른 서비스와 섞이지 않는다 | 대회 기간만 쓰는데 비용과 등록 시간이 든다. 가진 도메인은 이미 Cloudflare DNS다 |

## 결과

- 쉬워지는 것: 학교망에 열린 포트가 없다. 새 학생 주소는 Ingress 하나로 열리고 DNS · 인증서를 건드리지 않는다.
- 어려워지는 것: 터널 클라이언트가 리더에 있어 리더가 꺼지면 방문자도 끊긴다(워커로 옮기는 것은 후순위). 방문자 트래픽이 Cloudflare를 거친다. 도메인이 개인 소유라 대회 뒤 와일드카드 · 터널을 지우는 일이 반납 목록에 들어간다.
- 다시 볼 조건: 학교망이 7844를 막을 때(AWS 입구 대안), 리더가 꺼져도 열려야 할 때(터널을 워커 둘로), 대회 뒤에도 서비스를 이어갈 때.
